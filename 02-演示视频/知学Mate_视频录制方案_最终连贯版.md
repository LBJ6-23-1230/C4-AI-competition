# 知学 Mate · 演示视频最终连贯版

> 队伍：暗影骑士王们  
> 最终文件名：`02-演示视频+暗影骑士王们.mp4`  
> 核心叙事：**一个空白账号，如何通过真实输入逐步形成课程、知识、画像、错题、计划和学习关系。**

---

## 一、最终选择：先空白，再展示变化

采用“空白账号 → 导入 → 形成个性化结果”的方案，比直接使用已经填满数据的账号更好。

它能同时证明：

1. 页面里的课程、DDL、知识点和画像不是写死的演示数据。
2. 后续对话、诊断、错题和搭子匹配都来自前面真实输入。
3. 同一个账号的数据在多个页面间确实连通。

但空白状态不要停太久。登录后只用 **5–7 秒**快速展示：

- 学习页还没有课程与 DDL；
- 知识库为空；
- 对话首页提示可以上传课程、考试和错题。

然后立即进入导入。整支视频不是比较 UI，而是证明“输入怎样驱动后续结果”。

## 二、三种课程与 DDL 导入怎么安排

### 推荐分工

| 方式 | 视频中负责什么 | 是否真正确认导入 | 原因 |
|---|---|---:|---|
| 图片识别 | 导入课程表 | 是 | 最直观，能展示多模态识别、预览和人工校正 |
| 文件导入 | 导入作业 DDL 的 CSV/JSON 文件 | 是 | 结构化、稳定、速度快，适合展示真实文件处理 |
| 粘贴导入 | 展示支持粘贴 JSON/CSV 和模板 | 默认否 | 证明灵活性即可，避免重复导入覆盖前面的列表 |

当前实现中，导入课程或 DDL 默认会**替换同类型列表**。因此不要依次确认三种方式导入同一类数据，否则后一步可能覆盖前一步，画面会显得数据忽多忽少。

### 图片导入课程表

正式镜头完整展示：

1. 选择一张裁剪清楚的课程表图片；
2. 出现“正在调用识别服务”；
3. 展示识别预览、模型来源和课程数量；
4. 人工修改一门课程的名称、考试日期或优先级；
5. 点击“确认导入并更新计划”；
6. 切到课程列表，看到课程真实出现。

这段最能体现 AI 输入能力，建议保持完整。

### 文件导入 DDL

使用提前准备好的 `DDL演示.csv`，内容只放 2–3 条，字段完整：

```csv
课程名称,作业标题,截止日期,优先级,预计时间
数据结构,二叉树实验报告,2026-10-02,高,90
离散数学,图论作业,2026-10-05,中,60
```

镜头展示选择文件、自动识别为 DDL、导入成功和“紧急任务”数量变化。

### 粘贴导入

只展示 4–6 秒：

1. 展开手动输入区；
2. 点击 CSV 或 JSON 模板；
3. 粘贴内容；
4. 镜头停在“解析并导入”按钮前。

旁白说明这是没有现成文件时的快速入口。主片默认不点击确认，避免覆盖已经导入的 DDL。若后续代码改为追加导入，再考虑真正提交。

## 四、逐段录制脚本

### 第 1 段：真实登录与空白状态（0:00–0:22）

**画面**

1. 登录页展示登录、注册、密码、验证码和华为账号入口。
2. 使用账号 A 的昵称与密码登录，手机号留空，避免个人信息入镜。
3. 登录后快速切到“学习”：课程与 DDL 为空。
4. 打开“我的知识库”：显示“还没有课程资料库”。
5. 回到对话首页。

**旁白**

> 这是一个刚建立的真实账号。现在它还没有课程、作业、知识库和学习画像。接下来，我们不加载预置结果，而是从学生自己的资料开始建立学习空间。

**要求**

- 空态镜头只停留 5–7 秒。
- 账号 A 必须是专用演示账号，不显示真实手机号。
- 为便于多次录制，提前准备可恢复到空态的账号或受控数据备份。

---

### 第 2 段：导入课程表与 DDL（0:22–1:02）

**画面 A：图片识别课程表，约 23 秒**

1. 学习 → 课程与作业 → 导入。
2. 点击“从相册导入课表图片”。
3. 识别等待段 2× 加速，并标注真实耗时。
4. 展示课程预览。
5. 校正一项信息并确认导入。

**画面 B：文件导入 DDL，约 12 秒**

1. 点击“导入作业 DDL”。
2. 选择提前准备好的 CSV。
3. 展示自动识别和导入成功。
4. 快速扫过 DDL 列表和紧急数量。

**画面 C：粘贴入口，约 5 秒**

1. 展开手动输入区。
2. 点击模板，展示 JSON/CSV 均可。
3. 不确认导入，直接转入下一段。

**旁白**

> 课程数据支持三种入口。课表截图交给多模态模型识别，识别结果先预览、可人工校正，再写入计划；结构化的作业 DDL 可以直接从 CSV 或 JSON 文件导入；没有文件时，也可以使用模板粘贴数据。导入完成后，课程会同步为可诊断的知识点。

**关键镜头**

必须拍到页面提示：`已为你的 X 门课准备 X 个知识点，点“开始诊断”即可练习。`

---

### 第 3 段：建立知识库并检索（1:02–1:32）

**画面**

1. 创建“数据结构”课程资料库。
2. 上传提前准备的 Markdown、TXT 或 DOCX 讲义。
3. 展示“已解析 X 个片段、X 个知识点”。
4. 点击正文，快速展示真实切片。
5. 进入检索测试，查询：`后序遍历为什么最后访问根节点？`
6. 展示命中的文件名、标题路径、正文片段和当前检索方式。

**旁白**

> 课程资料可以进入独立知识库。系统解析正文、切分片段并提取知识点；后续回答不仅给结论，还能回到具体文件和原文片段。页面会如实显示当前使用的是混合语义检索，还是关键词与标签检索。

**录制建议**

- 主片优先用 Markdown、TXT 或 DOCX，解析最稳定。
- 不用扫描版 PDF；它需要额外 OCR，现场风险高。
- 只有页面显示 `hybrid:semantic+keyword+tag` 时才说语义检索已生效。
- 页面显示 `keyword+tag` 时就按实际模式配音。

---

### 第 4 段：对话模式与历史会话（1:32–2:12）

六个模式都可以出现，但不能每个完整等待二三十秒。

**深度展示两个模式**

1. 今日学习建议：证明它读取了刚导入的课程和 DDL。
2. 今日任务：证明紧急作业已经进入对话结果。

**快速蒙太奇四个模式**

- 错题诊断；
- 学情画像；
- 学习搭子；
- 更新学习画像。

每个只保留“点击 → 回复来源标签 → 结构化卡片”3–4 秒。等待镜头统一加速并标注。

**历史会话**

最后打开侧边菜单的“历史会话”，展示刚才生成的多条会话记录，再点击其中一条恢复上下文。

**旁白**

> 对话不是六个互不相干的机器人入口，而是同一个学习秘书的六种任务模式。它能读取刚导入的课程、DDL、知识库、画像和错题；每次回复都会标明来自大模型还是规则兜底。历史会话则保留学生之前的问题和结果，方便继续追问。

**剪辑纪律**

- 六种模式必须来自真实操作素材，可以分开录制后按顺序剪辑。
- 不用旧历史记录冒充本次刚生成的结果。
- 历史会话录制前清理重复测试记录，只保留名称不同、内容清楚的 5–6 条。

---

### 第 5 段：题目诊断与学情画像（2:12–2:58）

**画面**

1. 从“学情画像”或“开始诊断”进入知识点选择页。
2. 选择由导入课程生成的最薄弱知识点。
3. 展示三道快速诊断题。
4. 完成作答并提交，其中故意错一道。
5. 展示正确率、掌握度变化、错误类型和 Trace ID。
6. 点击“查看题目与逐题解析”。
7. 返回学情画像，展示雷达图或知识点排序已经变化。

**旁白**

> 导入课程后，系统会生成可以练习的知识点。三道诊断题由服务端判分，错误题会形成具体错误类型，掌握度和后续计划也随结果更新。这里的数值来自确定性规则，不由模型临场生成。

**数字口径**

- 若使用空白真实账号，最终数字以页面真实结果为准，不强行要求 42→58。
- 如果 PPT 必须使用 42→58，则账号 A 必须提前准备对应起始画像；不要通过后期字幕伪造。

---

### 第 6 段：错题本（2:58–3:23）

**画面**

1. 在逐题解析中展示答错题已自动加入错题本。
2. 打开错题本，按课程看到该题。
3. 点击“刷题”，完成一次正确作答。
4. 展示 `已答对 1/3`。
5. 用短蒙太奇展示三次正确后自动移出的结果；若未提前准备素材，只展示规则说明，不伪造三次完成。

**旁白**

> 诊断中答错的题会自动进入错题本，并按课程整理。重练时系统保留解析和正确次数；同一道题累计答对三次后自动移出，让错题本逐渐收敛，而不是越积越多。

---

### 第 7 段：搭子匹配、换账号接受（3:23–4:03）

使用两个模拟器，但明确它们展示的是**两个账号通过后端协作**，不是鸿蒙分布式同步。

**设备准备**

- Pura 90：登录账号 A。
- MatePad Pro 13 或第二个手机模拟器：提前登录账号 B。
- 账号 B 已填写与 A 相同的课程目标、重叠空闲时间及互补知识结构。

**画面**

1. A 打开学习搭子页。
2. 展示最佳候选 B、总分和五因子拆解。
3. A 点击“向该搭子发起学习邀请”。
4. 切成同屏：左侧 A 显示发送成功，右侧 B 打开搭子页收到邀请。
5. B 点击“接受”。
6. 两端显示已建立搭子关系或协同任务。

**旁白**

> 搭子匹配综合学习目标、时间重叠、知识互补、基础信息和学习稳定性五个因子。账号 A 发出的不是本地假按钮，而是真实服务端邀请；账号 B 登录后可以收到并接受，双方随后建立学习联系。

**要求**

- 两个模拟器上方加清晰角标：`账号 A｜发起邀请`、`账号 B｜接收邀请`。
- 匹配分以页面真实结果为准，不写死 80 或 90。
- 不把这一段称为“跨设备接续”；它证明的是跨账号邀请闭环。

### 第 8 段：回看导入后的变化（4:03–4:22）

**画面**

与开头空态做快速前后对照：

- 学习页：出现课程、紧急 DDL 和当前任务；
- 知识库：出现数据结构资料库、文档和知识点；
- 学情画像：出现掌握度与诊断历史；
- 错题本：出现刚刚答错的题；
- 我的：出现学习搭子和学习数据。

**旁白**

> 回到最初的账号，刚才还是空白的学习空间，现在已经拥有课程、作业、知识库、掌握度、错题和学习搭子。所有变化都来自前面的真实输入和操作。

这一段是全片最重要的“前后对比”，比在开头长时间展示空白页更有力量。

### 第 9 段：修改密码（4:22–4:34）

修改密码会让当前会话失效并回到登录页，因此必须放在业务演示结束后。

**画面**

1. 我的 → 修改密码。
2. 输入原密码、新密码并确认。
3. 页面提示修改成功，返回登录页。
4. 快速展示使用新密码重新登录成功。

**旁白**

> 账号体系也完成了基本闭环：密码只保存加盐哈希，修改后旧会话立即失效，并要求使用新密码重新登录。

**建议**

- 使用专门的账号 C 或在最后一条素材中操作，避免破坏账号 A 的主线录制状态。
- 密码全程保持掩码，不公开具体内容。
- 注销账号只在答辩备用素材中展示，不放主片，避免不可恢复操作。

### 第 10 段：后端证据与设备适配（4:34–4:45）

**后端是否需要展示：需要录，但主片只放 3–5 秒。**

建议使用画中画：

- 主画面仍是 App；
- 右侧小窗显示经过脱敏的实时请求；
- 只保留三条有代表性的接口：课程图片识别、Agent 对话、搭子邀请；
- 同时保留 App 的“大模型生成 / 本地规则兜底”标签。

示例：

```text
POST /api/v1/import/schedule-image      200
POST /api/agent/chat                    200   llmUsed=true
POST /api/v1/partner-invitations        201
```

注意：HTTP 200 只能证明接口成功。大模型是否实际使用，必须结合 `llmUsed=true` 或 App 来源标签。

余下 5–6 秒可展示 Pura 90 竖屏与 MatePad Pro 13 横屏布局。只说手机和平板适配，不声称两个模拟器完成了鸿蒙分布式数据同步。

**画面**

快速闪回：导入、检索、诊断、错题、搭子接受、前后对比，最后定格产品名和团队名。

片尾核心句：

## 五、后端画面到底怎么处理

### 主片

只出现一次，3–5 秒，作为真实性辅助证据。

### 答辩备用素材

单独录一条 30–60 秒的完整证据视频，包含：

1. App 操作与后端日志同屏；
2. 接口路径、状态码和响应来源；
3. `llmUsed=true/false`；
4. 搭子邀请创建、接收和接受；
5. 不包含 API Key、Token、手机号、图片 Base64 或真实路径。

### 不建议

- 在主片现场启动后端；
- 长时间滚动终端；
- 打开大段源码；
- 把 HTTP 200 当作调用大模型的唯一证据；
- 为了拍日志让 App 只占很小一块、导致评委看不清产品界面。

## 六、录制前的数据准备

### 账号 A：主线账号

- 开始时为空账号；
- 能登录、修改密码；
- 录制中导入课程、DDL 和知识库；
- 用于诊断、错题、搭子邀请。

### 账号 B：搭子账号

- 提前注册并登录第二个模拟器；
- 有相同课程目标；
- 与 A 有重叠空闲时间；
- 有互补知识结构；
- 能收到、接受 A 的邀请。

### 账号 C：安全功能账号

- 专门用于修改密码素材；
- 避免修改账号 A 后影响前面主线的补录。

### 文件素材

- 一张裁剪清楚的课程表 PNG/JPG；
- 一个只含 2–3 条记录的 DDL CSV；
- 一份 1–3 页的 Markdown、TXT 或 DOCX 课程讲义；
- 一份粘贴用的短 JSON/CSV 模板；
- 所有文件名使用中文业务名称，不出现“test”“mock”“fixture”。

## 七、必须提前处理的画面问题

根据当前截图，正式录制前应处理：

1. 账号昵称不要使用 `test5`，改成自然的演示昵称。
2. 历史会话中重复三条“帮我看看我的薄弱知识点”应清理，只保留不同能力的记录。
3. 知识库空态顶部留白较大，录制时可从创建区域开始裁切，或在进入后立即操作。
4. 快速诊断页内容很长，录制时只保留第一题、提交按钮和结果页关键区域，不持续慢滚。
5. 后端窗口必须脱敏并放大字体，确保三条日志在 1080p 下可读。
6. 模拟器状态栏时间保持连续，避免多个素材时间跳变明显；无法统一时可适度裁掉顶部状态栏。

## 八、最终验收

- [ ] 同一个账号 A 从空态一路形成课程、知识库、画像和错题。
- [ ] 图片课程识别有预览和人工确认，不是直接假成功。
- [ ] 文件导入用于 DDL，粘贴导入没有覆盖已有数据。
- [ ] 知识库展示了正文、来源片段和真实检索模式。
- [ ] 六个对话模式均出现，至少两个完整展示。
- [ ] 历史会话没有重复测试垃圾记录。
- [ ] 诊断结果、掌握度变化和错题本形成连续因果关系。
- [ ] 搭子邀请由账号 A 发起、账号 B 实际收到并接受。
- [ ] 修改密码放在主业务结束后，密码全程掩码。
- [ ] 后端画面不超过 5 秒且无敏感信息。
- [ ] 两个模拟器没有被描述为鸿蒙分布式同步成功。
- [ ] 最终成片小于 5 分钟，文件名完全正确。
