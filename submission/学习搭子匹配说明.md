## 二、五因子评分模型

后端 `app/agent/partner_match.py` 的 `score_partner()`，满分 **100**：

| 因子 | 满分 | 判定规则 |
|---|---|---|
| **目标一致** `goal` | 30 | 课程与目标**完全相同**得 30；仅课程相同得 20；否则 0 |
| **时间重叠** `timeOverlap` | 30 | 空闲时段重叠 ≥120 分钟得 30；≥60 得 20；≥30 得 10；否则 0 |
| **知识互补** `knowledgeComplement` | 20 | 你弱我强 + 我弱你强的知识点对数 ≥2 得 20；=1 得 10；否则 0 |
| **基础匹配** `basicMatch` | 10 | 年级与专业都相同得 10；仅年级相同得 5；否则 0 |
| **稳定性** `stability` | 10 | 候选人空闲时间段恰为 1 段得 10；有多段得 5；无得 0 |

响应里同时给出 `overlapMinutes`（实际重叠分钟数），
这样页面能解释"为什么时间重叠是 20 分而不是 30 分"。

## 三、演示基线的真实结果（可直接引用）

用演示数据（小明 u001 vs 小红 u002 / 小刚 u003）**实测输出**：

| 排名 | 候选人 | 总分 | 目标 | 时间重叠 | 知识互补 | 基础 | 稳定 |
|---|---|---|---|---|---|---|---|
| 🏅 1 | **小红** | **90** | 30 | 20（重叠 **60 分钟**） | 20 | 10 | 10 |
| 2 | 小刚 | **60** | 30 | 0（重叠 **0 分钟**） | 10 | 10 | 10 |

### 为什么小红是 90 分

| 因子 | 得分 | 依据 |
|---|---|---|
| 目标一致 | 30 | 两人都是「数据结构 / 期末80+」，**完全相同** |
| 时间重叠 | 20 | 小明 20:00–22:00、小红 21:00–23:00 → 重叠 **60 分钟**（≥60 但 <120） |
| 知识互补 | 20 | 小明弱「二叉树遍历/递归理解」∪ 强「图算法」；小红弱「图算法」∪ 强「递归理解」→ **2 对** |
| 基础匹配 | 10 | 都是「大二 · 计算机科学与技术」 |
| 稳定性 | 10 | 小红空闲时间恰为 1 段 |

### 小刚为什么只有 60 分

* 时间重叠 **0 分钟**（小明 20:00–22:00、小刚 19:00–20:00，**边界相接不算重叠**）
* 知识互补只有 **1 对**（小刚强「二叉树遍历」，但小明的弱项里「图算法」与小刚的弱项重复，不构成互补对）

> 这两个数字**可复现**：同一份资料每次结果完全一致。
> 验证命令见本文第五节。

## 四、页面展示什么

联机模式下页面分三块：

1. **最佳匹配卡** —— 姓名、年级/专业/课程、总分（满分 100）、空闲时间、
   一行说明「分数由后端确定性算法给出：同一份资料每次结果完全一致，可复核」
2. **匹配因子分析** —— 五个因子逐项列出「得分 / 满分」与**判定依据**；
   达满分的因子标绿（`#0F766E`），未满分标橙（`#B45309`）
3. **其他候选人** —— 姓名、年级/专业/课程、实际重叠分钟数、知识互补得分、总分

另有三种状态，**都不伪装成结果**：

| 状态 | 展示 |
|---|---|
| 请求中 | 转圈 + 「正在计算匹配度…」 |
| 请求失败 | 红框 + **真实错误原因** + 「重试」「前往环境设置」，并明确写出「为避免把本地规则结果伪装成在线 Agent 结果，这里如实显示失败原因，而不是退回本地算分」 |
| 全部 0 分 | 「暂无可匹配的候选人」+ 说明「后端已返回结果，但所有候选人的匹配分都为 0」 |

## 六、实现要点与踩过的坑

### 6.1 ArkTS 不接受 `ApiResult` 的联合类型收窄

无论写 `if (!result.ok)` 还是 `if (result.ok) {...} else { result.error }`，
**访问 `.error` 都会编译失败**：

```
Error Message: Property 'error' does not exist on type 'ApiResult<PartnerMatchResponse>'.
```

解决办法与既有代码 `AuthClient.describe()` 一致 —— 抽一个方法 + **显式 cast**：

```ets
private static describeFailure(result: ApiResult<PartnerMatchResponse>): string {
  const failure = result as ApiFailure;
  if (failure.error.code === 'NETWORK_ERROR') { return '连接不上后端服务…'; }
  return failure.error.message;
}
```

> 这个坑花了三次编译才定位，写在这里避免后人重复踩。

### 6.2 为什么不复用离线 Fixture 的渲染

后端因子是**分值**（30/30/20/10/10），本地 `LocalAgentService` 的因子是**百分比**。
合在一起渲染会让人误以为是同一套算法，所以联机与离线**分开渲染**：

| 模式 | 数据来源 | 渲染方法 |
|---|---|---|
| 联机 | 后端五因子算分 | `OnlineBestCard` / `OnlineFactorBoard` / `OnlineOtherRow` |
| 离线 | 本地规则 | `MatchScoreBoard`（原有） |
