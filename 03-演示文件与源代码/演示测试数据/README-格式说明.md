# 知学Mate · 演示测试数据

> 用于**功能演示**与**录屏**时导入课程表与作业 DDL。
> 所有日期都是**未来日期**（相对 2026-09 中下旬），保证导入后能算出合理的剩余天数与优先级。

---

## 一、两种导入方式（对应 App 内两个入口）

| 方式 | 入口 | 说明 |
|---|---|---|
| **上传文件** | 课程导入页 → 「选择文件导入」 | 系统文件选择器，**选 CSV 或 JSON 文件** |
| **复制粘贴** | 课程导入页 → 下方文本框 → 「粘贴导入」 | 直接粘贴 JSON 或 CSV 文本内容 |

> ⚠️ **粘贴必须去「课程导入」页**。对话页**不解析**粘贴的文本 ——
> 它读取的是「已导入」的数据（课程导入页会显示「已导入」状态）。

程序按 **首个字符** 自动判断格式：以 `{` 或 `[` 开头 → 按 JSON 解析，否则按 CSV 解析。

## 三、字段格式

> **格式已放宽**（2026-09-24）：下面列的是**推荐写法**，不再要求"严格照写"。
> 解析器现在会自动识别更多写法 —— 详见 [3.5 格式有多宽松](#35-格式有多宽松2026-09-24-放宽)。

### 3.1 课程表

| 字段 | 必填 | 格式 | 说明 |
|---|---|---|---|
| `courseName` | ✅ **必填** | 文本 | 缺这条**该行被跳过**；CSV 缺这一列会直接报错 |
| `examDate` | 选填 | `YYYY-MM-DD` | 缺省为 `未设置` |
| `priority` | 选填 | `高` / `中` / `低` | 缺省按剩余天数自动推断 |
| `studyHours` | 选填 | 数字 | 缺省 `0` |
| `status` | 选填 | 文本 | 缺省按学习时长自动推断 |

**CSV 支持的表头别名**（中英文皆可，大小写与空格不敏感）：

| 字段 | 可用表头 |
|---|---|
| `courseName` | `courseName` · `course` · `name` · `课程名称` · `课程名` · `课程` · `科目` · `名称` · `学科` |
| `examDate` | `examDate` · `exam` · `date` · `考试日期` · `考试时间` · `考试` · `日期` |
| `priority` | `priority` · `优先级` · `重要程度` · `重要度` · `紧急程度` |
| `studyHours` | `studyHours` · `hours` · `学习时长` · `每周学时` · `学时` · `时长` · `学习时间` · `复习时长` |
| `status` | `status` · `复习状态` · `状态` · `进度` · `复习进度` |

### 3.2 作业 DDL

| 字段 | 必填 | 格式 | 说明 |
|---|---|---|---|
| `title` | 建议填 | 文本 | 缺省为 `未命名任务` |
| `courseName` | 选填 | 文本 | 缺省为 `未分类` |
| `dueDate` | 选填 | `YYYY-MM-DD` | 缺省为 `未设置` |
| `priority` | 选填 | `高` / `中` / `低` | 缺省自动推断 |
| `estimatedMinutes` | 选填 | 数字（分钟） | 缺省 `30` |

**CSV 支持的表头别名**（大小写与空格不敏感）：

| 字段 | 可用表头 |
|---|---|
| `courseName` | 同 3.1（`课程名称` · `课程名` · `科目` …） |
| `title` | `title` · `name` · `homework` · `作业标题` · `标题` · `作业名称` · `作业` · `任务` · `任务名称` · `内容` |
| `dueDate` | `dueDate` · `due` · `deadline` · `ddl` · `截止日期` · `截止时间` · `截止` · `到期` · `到期日` |
| `priority` | 同 3.1 |
| `estimatedMinutes` | `estimatedMinutes` · `minutes` · `预计时长` · `预计时间` · `预计用时` · `预计分钟` · `预计` · `分钟` |

### 3.3 自动推断规则（不填 priority / status 时）

| 剩余天数 | 推断优先级 |
|---|---|
| ≤ 3 天 | 高 |
| 4–10 天 | 中 |
| > 10 天 | 低 |

| 学习时长 | 推断复习状态 |
|---|---|
| ≤ 1 小时 | 近期复习不足 |
| 2–4 小时 | 近期复习正常 |
| ≥ 5 小时 | 近期复习良好 |

### 3.4 用哪个解析器由「你选的类型」决定（重要）

App 里两个解析器**独立存在**，走哪一个由当前选择决定：

| 导入方式 | 由什么决定用哪个解析器 |
|---|---|
| **粘贴导入** | 上方的**类型选择**（课程 / 作业 DDL） |
| **上传文件** | 当前的**标签页**（课程 / 作业 DDL / 导入） |

> ⚠️ 页面上的「类型选择」与「标签页」都要选对，否则会用错解析器。

**两个解析器都认 `课程名称` 这一列**（它是课程与 DDL 的公共列），
所以用错解析器时**通常不报错**，但结果不对：

| 实际文件 | 选错成 | 后果 |
|---|---|---|
| `02-课程表.csv`（只有课程表头） | 作业 DDL | 把 3 门课当成 **3 条「未命名任务」**导入 —— 不报错，但内容错 |
| `03-作业DDL.csv`（有 `作业标题` 列） | 课程 | 把 4 行按 `课程名称` 读成 **4 门「考试未设置」的课** |

> 这是**两个解析器字段别名重叠**导致的，不是数据文件的问题。
> 演示时请**明确选对类型**；§6.2 的粘贴步骤里已写明每一步该选什么。

**唯一能一个文件覆盖两类的是 `01-课程与作业完整示例.json`**：
它同时含 `courses` 与 `ddls` 两段，**分两次、选对类型**各导一次。

### 3.5 格式有多宽松（2026-09-24 放宽）

真实场景里没人会照着我们定的表头写字，所以解析器不再要求"严格照写"。现在支持：

**① 日期**（原来只认 `2026-10-15` 这种 `new Date()` 吃得下的写法）

| 写法 | 结果 |
|---|---|
| `2026-10-15` · `2026/10/15` · `2026.10.15` | ✅ |
| `2026年10月15日` · `2026年10月15` | ✅ |
| `10月15日` · `10/15` · `10-15` | ✅ 只给月日时补当前年；若那天已过，按**明年**算（学期跨年是常态） |
| `2026-02-30`（不存在）· `13月1日` · `下周三` · `待定` | ❌ **如实报错**，见下 |

> ⚠️ 这一条修的是一个**静默错误**：原实现把认不出的日期丢给 `new Date()`，
> 拿到 `NaN` 后一路传下去，`guessPriority(NaN)` 会**悄悄落成"低"** ——
> 不报错、不提示，用户以为导入成功，但优先级是错的。
> 现在改成明确报错并说清支持的写法，例如：
> `第 4 行的考试日期认不出来：「待定」。支持的写法：2026-10-15、2026/10/15、2026年10月15日、10月15日。`

**② 分隔符**：半角逗号 · **制表符**（从 Excel / 教务系统网页直接复制出来最常见）· **中文逗号** · 分号 —— 按行内出现次数自动判定。

**③ 没有表头也行**：直接从表格里复制的纯数据（第 1 行就是数据）会被自动识别，按约定列序解析：

```
课程表：课程名称, 考试日期, 优先级, 学习时长, 复习状态
作业DDL：课程名称, 作业标题, 截止日期, 优先级, 预计时长
```

> 判定方式：认不出表头时，看第 1 行**第 2 列能不能解析成日期** ——
> 能就当数据（无表头），不能就说明第 1 行确实是我们没认出的表头，
> **如实报错**而不是把表头当数据吃进去。

**④ 别名表**见 3.1 / 3.2。匹配时**大小写与首尾空格不敏感**（`CourseName`、`课程名称 ` 都能认）。
另外从 Excel 导出的 CSV 常带 UTF-8 BOM，解析器已处理，不影响第一列。

> 权威实现在 `app/entry/src/main/ets/services/FileParserService.ets`；
> 对应的回归闸门是 `tools/check_parser_rules.js`（**45 项断言**，
> 用 DevEco 自带 node 跑，无需装依赖），改解析规则后请一并跑它。

## 四、JSON 的两种写法（都支持）

**写法 A（推荐）** —— 容器对象，可同时带课程与作业：

```json
{
  "courses": [ { "courseName": "数据结构", "examDate": "2026-10-15", "priority": "高", "studyHours": 2, "status": "近期复习不足" } ],
  "ddls":    [ { "courseName": "数据结构", "title": "二叉树遍历实验报告", "dueDate": "2026-09-26", "priority": "高", "estimatedMinutes": 45 } ]
}
```

**写法 B** —— 裸数组（只能导一类，注意别和另一类混在一起）：

```json
[ { "courseName": "数据结构", "examDate": "2026-10-15", "priority": "高", "studyHours": 2, "status": "近期复习不足" } ]
```

> 「课程表」按钮只读 `courses` 段，「作业 DDL」按钮只读 `ddls` 段。
> 所以**同一个文件可以分两次点两个按钮**，各导一半 —— 这正是 CSV 做不到的。

## 五、CSV 注意事项

- 表头行**可省**（2026-09-24 放宽）：没有表头时按约定列序解析，见 [3.5](#35-格式有多宽松2026-09-24-放宽)。
  若写了表头但**一个字段都没认出来**，会**如实报错**而不是把表头当数据 —— 这种多半是名字写岔了。
- 字段内含**逗号**时，用**英文双引号**包起来（解析器支持引号转义），例：
  ```csv
  课程名称,作业标题,截止日期,优先级,预计时长
  数据结构,"图算法习题（第 6 章, 含附加题）",2026-09-29,中,60
  ```
- 编码用 **UTF-8**（带不带 BOM 都可）
- 空行会被跳过

## 六、演示操作步骤（可直接照做）

### 6.1 上传文件演示

1. App → 首页 → 进入**课程导入**页
2. **先点上方标签页，让「课程」处于选中状态** ← 这一步决定用哪个解析器
3. 点「**选择文件导入**」→ 在文件选择器里选 `02-课程表.csv`
4. 页面显示「**已导入**」并提示「成功导入 3 门课程」
5. 切到「作业 DDL」标签页 → 再点「选择文件导入」→ 选 `03-作业DDL.csv`
   → 提示「成功导入 4 项作业」
6. 切到「学习计划」页 → 任务会带上新导入的 DDL

> 想一个文件覆盖两类：步骤 2 选「课程」导 `01-课程与作业完整示例.json`，
> 再切「作业 DDL」标签页导同一个文件。
>
> 录屏提示：文件选择器要提前把文件放到**易找的位置**（如「下载」或根目录），
> 别现场翻目录。若设备上没有文件管理器，改用 6.2 的粘贴演示更稳。

### 6.2 粘贴演示（更稳，推荐录屏用）

1. 课程导入页 → **类型选择里选「课程」** → 展开文本框
2. 打开 `05-粘贴用-课程.txt`，**全选复制**，粘贴进文本框
3. 点「**粘贴导入**」→ 提示「成功导入 3 门课程」
4. 把**类型选择切到「作业 DDL」** ← 必须切，否则会当成课程解析
5. 打开 `06-粘贴用-作业DDL.txt` 复制 → 粘贴 → 点「粘贴导入」
   → 提示「成功导入 4 项作业」

> 程序按首个字符自动判别 JSON / CSV：以 `{` 或 `[` 开头走 JSON 解析，否则按逗号切分。
> 本目录两份 `.txt` 都是 JSON 写法。

### 6.3 出错时会看到什么（也可以主动演示「健壮性」）

以下提示语均**逐条核对自源码**：

| 你导入的内容 | App 的提示 |
|---|---|
| 文本框为空 | 请输入 JSON 或 CSV 数据内容 |
| CSV 只有表头一行 | CSV 中未解析到任何有效课程数据 |
| CSV 表头一个字段都没认出来（且不像数据） | 课程表：`CSV 表头缺少课程名称列。可识别的列名：课程名称 / 课程名 / 科目 / 名称 / courseName。`<br>作业 DDL：`CSV 表头缺少作业标题列或截止日期列。…` |
| 日期写了但认不出来 | 第 N 行的考试日期认不出来：「待定」。支持的写法：2026-10-15、2026/10/15、2026年10月15日、10月15日。 |
| JSON 语法错误 | 解析失败：`<具体报错>` |
| 文件选择器取消或读取失败 | 文件选择失败，请使用下方手动输入方式导入数据 |

> 建议演示一条错误提示，体现「错误处理给可读提示而不是崩溃」。
> 最直观的是**空文本框**或**只有表头的 CSV**。

## 七、想自己改数据时

- **日期改成未来**：`examDate` / `dueDate` 建议设在**今天之后**，
  否则剩余天数会被截断为 0、优先级全变成「高」，看不出区分度
- **课程名与作业的 `courseName` 保持一致**，演示时才能看出「哪门课的作业」
- 想演示**优先级拉开档次**：把 `dueDate` 分别设成 2 天后 / 6 天后 / 20 天后
