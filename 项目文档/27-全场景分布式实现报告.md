全前端搜索：

```
distributed* / dataObject / 流转 / 接续 / continueDevice   →  零命中

```

**但没有任何跨设备能力**。这是评委最容易追问、也最难解释的一点。

## 二、实现了什么

### 2.1 新增服务 `services/DistributedStateService.ets`（约 380 行）

用 `distributedDataObject` 建立**跨设备共享状态对象**：

```
   手机 FocusSetup 点「开始专注」
        │
        │  publishFocusTask(task)   ← 写入共享对象
        ▼
   ┌──────────────────────────────────────────────┐
   │  distributedDataObject                       │
   │  sessionId = zhixue_mate_study_continuity_v1 │
   │  { taskJson, deviceLabel, updatedAt, active }│
   └──────────────────────────────────────────────┘
        │
        │  on('change') / on('status')
        ▼
   平板 FocusSetup
        显示「手机正在专注：二叉树遍历实验报告」
        + 按钮「在这台设备上接着做」
```

同步内容是**当前专注任务**（课程、任务名、计划时长、专注模式、计时方式），
对应产品叙事里的「**手机上开始专注，平板上看到同一任务**」。

### 2.2 权限与配置

`module.json5` 新增两项（依据本机 SDK `toolchains/lib/PermissionDefinitions.json`）：

| 权限 | grantMode | 说明 |
|---|---|---|
| `ohos.permission.DISTRIBUTED_DATASYNC` | **user_grant** | 分布式数据同步必需；运行时弹框申请 |
| `ohos.permission.GET_NETWORK_INFO` | system_grant | 读取网络状态，安装即授予 |

`EntryAbility` 新增 `setupDistributedState()`：
先 `checkAccessTokenSync` 查授权，未授权则 `requestPermissionsFromUser` 弹框，
再按结果初始化服务。**失败不阻断任何主流程。**

### 2.3 UI 落点

`FocusSetup` 新增「**全场景接续**」卡片，四种状态如实呈现：

| 状态 | 显示 |
|---|---|
| 未授权 | 「开启「多设备协同」权限后…」 |
| 初始化失败 | 原样展示错误码（不吞掉） |
| 已连接无对端 | 「本机以「手机」身份加入协同会话…」 |
| 有对端任务 | 「**手机**正在专注：xxx」+「在这台设备上接着做」按钮 |

## 三、实测验证（两实例）

启动了 `Pura 90`（手机）+ `MatePad Pro 13`（平板）两个实例。

### ✅ 已验证通过

| 项 | 证据 |
|---|---|
| 编译 | `BUILD SUCCESSFUL`，ArkTS 编译 0 错误 |
| 权限弹框 | 实测弹出，且**自定义 reason 文案正确显示**：<br>「允许"知学Mate"发现和连接附近的设备？**用于在手机、平板等设备间同步当前学习任务与专注进度**」 |
| 双端授权 | 两台均成功授予 `DISTRIBUTED_DATASYNC` |
| **会话建立** | **两台都加入同一会话**：<br>`joined session zhixue_mate_study_continuity_v1`<br>`Distributed state ready, device=手机` / `device=平板` |
| 设备形态识别 | `deviceInfo.deviceType` → 手机 / 平板，标签正确 |
| UI 渲染 | 卡片在两台设备上都正常渲染，文案符合状态 |
| 任务发布 | 手机点「开始专注」→ 成功进入计时页（`44:46` 倒计时运行） |

### ❌ 未能验证：跨设备数据实际同步

**原因不是代码，是模拟器的架构限制。** 实测证据：

```
             手机 (127.0.0.1:5555)      平板 (127.0.0.1:5557)
eth0 IP      10.0.2.15                 10.0.2.15        ← 完全相同
eth0 MAC     52:54:00:12:34:56         52:54:00:12:34:56 ← 完全相同

手机 ping 平板 10.0.2.16   →  100% packet loss
手机 ping 宿主 10.0.2.2    →  ✅ 通
信任设备列表（两台）        →  dump trusted device list is empty
softbus_server             →  在运行
```

**每个模拟器实例都是独立的 QEMU NAT 沙箱**，IP 与 MAC 都相同，彼此不可达。
HarmonyOS 分布式组网依赖 softbus 在**真实局域网**上做设备发现与信任配对，
模拟器不具备这个条件 —— 这与"代码写得对不对"无关。

> 顺带说明：手机的 `HalDeviceManager` 日志出现过
> `GetScanInfos success, scan info size:1`，说明 softbus 的扫描流程在跑，
> 但**发现的设备无法建立可信连接**，因此对端始终 `offline`。

## 四、结论与建议

### 代码层面：已完成，且已通过所有可在本环境验证的环节

- 会话建立、权限流程、设备形态识别、UI 呈现、任务发布 —— 全部实测通过
- 跨设备同步的**唯一未验证环节是 softbus 组网**，这需要两台真机（同一 WiFi）

### 对答辩的建议

| 场景 | 可讲什么 |
|---|---|
| **有真机** | 现场演示：手机点开始专注 → 平板出现「手机正在专注：xxx」→ 点「接着做」 |
| **只有模拟器** | 演示单机卡片 + 说明"会话已建立、等待对端"，并**如实说明**模拟器无法跨实例组网（这本身是可信的技术解释，比含糊带过更好） |

> ⚠️ **不要**在没有真机演示的情况下声称"跨设备同步已验证"。
> 当前能证明的是"分布式会话已建立 + 代码路径完整"，不是"数据已跨设备流动"。

## 五、踩过的坑（存档）

### 1. `sessionId` 不允许连字符

最初写成 `zhixue-mate-study-continuity-v1`，实测报：

```
401 The sessionId allows only letters, digits, and underscores(_),
    and cannot exceed 128 in length.
```

会话根本建不起来。已改为下划线形式，并新增 `assertSessionIdValid()` 自检，
把"哪个字符不合法"直接写进日志与 UI 的 `lastError`（系统原报错不指出具体字符）。

### 2. `Context.applicationInfo` 是同步属性，不是方法

`abilityAccessCtrl.checkAccessTokenSync` 需要 `accessTokenId`，
`this.context.getApplicationInfo()` 是错的 —— 正确写法是
`this.context.applicationInfo.accessTokenId`（见 `@ohos.app.ability.Context.d.ts`）。

### 3. 忘记实现 `notify()`

首次构建报 10 条 `Property 'notify' does not exist`。
`notify()` 负责把快照推给 UI，且**必须 try/catch**：
监听者是页面组件，页面销毁后异步事件仍可能触发回调，
此时回调抛错会顺着分布式事件链往上冒，把一次正常状态变更变成崩溃。

### 4. `@State` 不要存整个快照对象

ArkUI 只观测 `@State` 变量本身的赋值，对对象内部字段不触发重渲染。
`FocusSetup` 里把快照摊平成多个顶层 `@State` 基本类型
（`syncReady` / `syncPeerCount` / `syncRemoteTask` …），避免"数据更新了但界面不动"。
