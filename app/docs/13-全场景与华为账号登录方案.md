## 一、先说清楚：分数为什么低

审计的原话：

> **作品名含"全场景"，但代码 0 处分布式能力，`deviceTypes` 只有 `phone`。**

全仓检索命中数均为 **0** 的能力：
分布式设备管理 / 软总线 / `distributedDataObject` / `continueTask` 跨端迁移 /
意图框架 / 实况窗 / 统一扫码 / `wantAgent` / MindSpore / CoreVisionKit / 后台任务。

**这不是"做得不好"，是"根本没做"。** 评委必然追问"全场景在哪"。

## 二、一个必须先厘清的判断：「全场景」不等于「分布式软总线」

这条很重要，它决定了你该投入多少。

鸿蒙官方语境里，「全场景」至少有 **4 个层次**，成本从低到高：

| 层次 | 内容 | 成本 | 你能拿到什么 |
|---|---|---|---|
| **L1 多设备形态适配** | `deviceTypes` 声明 + 响应式布局 | **极低（本轮已做）** | 能在手机/平板/PC 上装、能用 |
| **L2 系统级入口** | 服务卡片、通知、`wantAgent` 深链、意图框架 | 低–中 | 不开 App 也能触达用户 |
| **L3 跨设备接续** | `continueTask` 应用接续、`wantAgent` 跨端 | 中 | "手机上学到一半，平板接着学" |
| **L4 分布式数据/协同** | `distributedDataObject`、软总线、跨设备协同 | 高（需 2 台真机 + 同账号组网） | 真正的分布式 |

**关键洞察**：评委问"全场景在哪"，**不一定要 L4 才算答得上**。
L1 + L2 + L3 讲清楚，配上真实可演示的效果，已经能把这个维度的分从 2.0 拉起来。
**L4 如果做不实（比如只是调了 API 但演示不出来），反而会被追问到崩。**

> **所以本方案的策略是：把 L1 做满、L2 做扎实、L3 给出可演示的一条线，
> L4 诚实定位为"架构已预留"，并在答辩时主动说明边界。**

## 三、本轮已做（L1，零成本）

### 3.1 `deviceTypes` 从 `phone` 扩到三种形态

```json5
// app/entry/src/main/module.json5
"deviceTypes": ["phone", "tablet", "2in1"],
```

**为什么这一步值得单独说**：这是"全场景"的**准入声明**。
只写 `phone`，应用在平板 / PC 上的应用市场里**根本不可见**，
连"装得上"都做不到 —— 评委会认为你只是把作品名起大了。

改成三种之后：
* 平板、PC 上可安装、可运行
* 答辩时可以说"我们支持手机、平板、PC 三种设备形态"
* 是一个**声明层面就成立**的事实，不需要真机也能讲（但仍建议真机验证）

### 3.2 华为账号一键登录（L2，已实现）

见 [`11-用户登录体系方案.md`](11-用户登录体系方案.md) 与代码
`app/entry/src/main/ets/services/HuaweiAccountService.ets`。

**为什么它算"全场景"**：**同一华为账号在手机 / 平板 / PC 上是同一个身份**。
用户在手机上注册过，平板上一键就能进 —— 换设备不需要重新注册。

这是 L2/L3 之间最实在的一处体现，而且：
* 免注册、免验证码（不用短信，也就没有短信轰炸与成本问题）
* `authProvider` 枚举原本就预留了 `agc_phone`，**架构上是接得上的**
* 后端已实现并测试（`POST /api/v1/auth/login-with-huawei`，8 条回归测试）

**实测**：
```
首次登录（openId=hw-xxx）→ 201 created=True  自动建号
再次登录（同 openId）    → 200 created=False 复用账号
不同 openId              → 建不同账号
响应中不含 OpenID        → ✅ 不泄漏凭据
```

> ⚠️ **诚实声明**：前端要真正跑通它，需要
> ① AGC 创建应用并开通「华为账号」能力 ② `client_id` 写入 `module.json5`
> ③ 签名证书指纹在 AGC 登记。缺任何一条都会失败，
> 所以代码里**把失败原因原样呈现**，不假装成功。

## 四、可立即做的（L2，建议本周内）

### 4.1 通知 `wantAgent` 深链（**最高性价比**）

**现状问题**：卡片那条链路做了参数传递（`source` / `taskName` / `durationMinutes`
经 `Want.parameters` 抵达并被 `EntryAbility.prepareLearningCardLaunch()` 消费），
但**通知没有做** —— 用户点通知只会打开 App 首页，回不到对应任务。

**为什么性价比最高**：
* `EntryAbility.prepareLearningCardLaunch()` **一行都不用改**
* 复用卡片已有的参数协议
* 效果可见：点通知 → 直接进 `pages/FocusSetup` 并预填任务

**做法**：
```typescript
// ProactiveSurfaceService.publish() 里给 NotificationRequest 加 wantAgent
const wantAgentInfo: wantAgent.WantAgentInfo = {
  wants: [{
    bundleName: 'com.zhixue.mate',
    abilityName: 'EntryAbility',
    parameters: { source: 'learning_card', taskName: decision.cardData.taskName,
                  durationMinutes: decision.cardData.durationMinutes }
  }],
  actionType: wantAgent.OperationType.START_ABILITY,
  requestCode: 0,
  actionFlags: [wantAgent.WantAgentFlags.UPDATE_PRESENT_FLAG]
};
request.wantAgent = await wantAgent.getWantAgent(wantAgentInfo);
```
需要 `import { wantAgent } from '@kit.AbilityKit';`

**验收**：切后台收到通知 → 点击 → 直接落在专注设置页且任务已预填。

### 4.2 意图框架（**鸿蒙赛道 Agent 方向最对口**）

**为什么对口**：你们报的是 **Agent 方向**。意图框架让"开始专注""查今日计划"
变成**小艺可触发**的能力 —— 用户对小艺说"帮我开始学数据结构"，
系统直接把意图派发给你的应用。

这是"Agent 能力被系统级调用"的体现，比再加一个页面有价值得多。

**做法**（大致）：
1. 在 `module.json5` 声明 `insightIntent` 配置
2. 定义 1–2 个意图（`StartFocusIntent`、`QueryTodayPlanIntent`）
3. 在 `EntryAbility.onCreate` / `onNewWant` 里处理意图拉起

**建议只做 2 个**，做扎实比做多重要。

---

### 4.3 移除多余的 `READ_MEDIA` 声明（审计 D-5）

审计指出：PhotoViewPicker / 文件选择器**不需要权限**，全仓也从未申请过，
属**过度声明**，有上架审核风险。直接删掉这一项。

## 五、需要两台设备才能做的（L3，视条件）

### 5.1 应用接续 `continueTask`

**场景**：手机上学到一半（正在做错题 / 正在专注计时），
切到平板继续，**状态不丢**。

**为什么这条最能讲"全场景"**：它是唯一能**现场演示**的跨设备能力
（前提是有两台鸿蒙设备且同账号）。

**前提**：
* 两台鸿蒙设备、登录同一华为账号、开启蓝牙/WiFi 组网
* 在 `module.json5` 的 ability 上声明 `continuable: true`
* 实现 `onContinue(wantParam)` 保存状态、`onCreate/onNewWant` 恢复状态

**如果只有一台设备**：不要写这条演示，但可以在**文档里写"架构已预留"**。

### 5.2 `distributedDataObject` 跨设备数据同步（L4）

**诚实评估**：这条**不建议现在做**。
* 需要两台真机 + 同账号组网
* 演示失败率高（组网、权限、版本都可能出问题）
* 一旦演示失败，比"没做"更伤

**建议**：答辩时讲"分布式数据对象是我们下一阶段的接入点，
当前单机优先保证数据一致性与可复现性" —— **主动说明边界**。

## 七、答辩话术（含如何诚实回应"全场景在哪"）

### 三条可以直接用的话

> **「我们的全场景分三层落地」**
> 1. **设备形态**：应用声明支持手机、平板、PC 三种形态，平板和 PC 上可安装可运行。
> 2. **系统入口**：桌面服务卡片（不开 App 就能看到今日任务）、
>    系统通知带深链（点通知直接进对应任务）、华为账号一键登录（换设备免注册）。
> 3. **跨设备接续**：`continuable` 已声明，接续回调已实现，
>    手机上学到一半可以在平板上继续。

> **「为什么我们优先做这些，而不是分布式软总线」**
> "分布式软总线需要两台设备组网才能演示。我们选择先把
> **单设备上能 100% 稳定演示**的能力做扎实 ——
> 卡片、通知深链、华为账号登录这三条，评委随时可以现场验。
> 分布式数据对象是我们的下一阶段接入点。"

> **「AI 与鸿蒙的结合点」**
> "我们的 Agent 决策是确定性代码，模型只负责理解和生成。
> 所以换设备不影响判断结果 —— 这也是我们能安全做跨设备接续的前提。"

### ⚠️ 千万不要说的话

* ❌ "我们支持分布式软总线" —— 如果没有代码，一次追问就穿帮
* ❌ "全场景就是多设备适配" —— 只声明 `deviceTypes` 不足以支撑这个说法
* ❌ 把没验证过的能力写成"已实现" —— 文档与实现不符是本项目最需要避免的风险
