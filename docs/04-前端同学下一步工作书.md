## 七、🔧 建议顺手修的一个真问题：错误提示误导

### 问题

`AgentBridge.ets` 的 `parseResponse()` 抛出的解析错误，
会被 `callAgent()` 的 catch 兜底成**网络错误**：

```typescript
// AgentBridge.ets 约 116-124 行
} catch (err) {
  const detail: string = err instanceof Error ? err.message : '';
  if (detail.startsWith('服务')) {
    throw new Error(detail);
  }
  throw new Error('连接超时或网络不可用，请检查服务地址后重试。');   // ← 解析错误也会走到这里
}
```

**后果**：当后端返回的 `llmUsed` 不是 boolean（或 `card` 结构不对）时，
界面提示"连接超时或网络不可用" —— **排查时会往网络方向找，浪费大量时间**。

### 建议改法

```typescript
} catch (err) {
  const detail: string = err instanceof Error ? err.message : '';
  if (detail.startsWith('服务')) {
    throw new Error(detail);
  }
  // 数据结构/契约类错误直接透传，不要伪装成网络问题
  if (detail.includes('must be') || detail.includes('required')
      || detail.includes('invalid') || detail.includes('字段')) {
    throw new Error(`服务返回的数据结构与契约不一致：${detail}`);
  }
  throw new Error('连接超时或网络不可用，请检查服务地址后重试。');
}
```

> 这是一个**小改动但收益很大**的修复：把"契约错误"和"网络错误"分开，
> 后面出问题时能一眼定位。建议做。
