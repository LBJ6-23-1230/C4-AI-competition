## 2. Fixture 核心主链

### 2.1 初始化

1. 打开“全部工具 → 数据源设置”。
2. 点击“使用离线 Fixture”。
3. 点击“检测当前计划接口”。
4. 预期显示：`Fixture 返回 Plan V1`。
5. 如果之前完成过演示，进入 Agent Trace，点击“重置演示数据”。

### 2.2 诊断前画像

1. 打开知识画像。
2. 预期画像版本为 V1。
3. 预期“二叉树后序遍历”掌握度为 42。
4. 预期关联学习证据为 0 条。

### 2.3 练习与评估

1. 点击“开始诊断练习”。
2. 预期进入 3 道题页面；Fixture 返回很快时，“正在启动 Agent 会话…”可能无法被肉眼看到。
3. 未答完三题时，“提交诊断”应不可用。
4. 完成三题后连续点击提交按钮，预期只提交一次。
5. 预期结果：正确率 67%，掌握度 42 → 58。
6. 预期显示：Agent 状态“已完成”，状态版本 5。
7. 预期显示：Plan V2，二叉树后序遍历调整为 45 分钟。

### 2.4 更新后画像与轨迹

1. 点击“查看更新后的知识画像”。
2. 预期画像版本为 V2，掌握度为 58，证据为 1 条。
3. 返回结果页并点击“查看 Agent 决策过程”。
4. 预期依次显示 5 个步骤：学习秘书、薄弱点诊断、练习生成、学习评估、计划调整。
5. 预期状态版本从 1 连续到 5，所有步骤显示“成功”。

### 2.5 重置

1. 在 Agent Trace 底部点击“重置演示数据”。
2. 预期真实后端模式不显示该按钮。
3. 点击“查看重置后的知识画像”。
4. 预期恢复画像 V1、掌握度 42、证据 0 条和 Plan V1。

## 3. 慢请求与异常回归

### 3.1 无后端服务

1. 切换到“DevEco 模拟器后端”，但不启动电脑端服务。
2. 点击“检测当前计划接口”。
3. 预期按钮显示“正在检测…”，期间不可重复点击。
4. 超时后预期提示“连接超时或网络不可用”，页面不崩溃。
5. 切回 Fixture 后，预期旧错误和旧会话不会污染 Fixture 数据。

### 3.2 快速返回

1. 在真实后端未启动时打开知识画像或当前计划。
2. 请求未结束时立即返回上一页。
3. 预期不会自动跳回旧页面，也不会出现闪退。

### 3.3 非法响应

真实后端返回空正文时，前端应提示“服务未返回可解析的数据”；返回非 JSON 正文时，应提示“服务返回的数据格式不正确”，并要求联调同学检查响应。

## 4. 配置与恢复

1. 选择 Fixture，普通关闭并重新打开应用。
2. 预期数据源仍为 Fixture。
3. 启动一次诊断后，普通关闭并重新打开应用。
4. 预期保留当前 `sessionId/traceId`，并重新向所选数据源查询状态。
5. 切换数据源后，预期旧 Workflow 会话被清除。
6. 卸载应用会清除本地偏好设置，这属于系统正常行为。

## 5. 真实联调接口矩阵

| 方法 | 路径 | 前端用途 | 当前状态 |
| --- | --- | --- | --- |
| POST | `/api/v1/workflows` | 创建诊断 Workflow，取得 `sessionId/traceId` | 等待正式后端契约 |
| GET | `/api/v1/workflows/{sessionId}` | 查询 Agent、状态版本和最终动作 | 等待正式后端契约 |
| GET | `/api/v1/profile/{userId}` | 读取画像、掌握度、历史和 Evidence | 等待正式后端契约 |
| GET | `/api/v1/plans/current` | 读取当前权威学习计划 | 等待正式后端契约 |
| GET | `/api/v1/exercises/{setId}` | 读取诊断练习集 | 等待正式后端契约 |
| POST | `/api/v1/exercises/{setId}/submit` | 提交答案并读取评估、掌握度更新及重规划 | 等待正式后端契约 |
| GET | `/api/v1/plans/{planId}/diff` | 读取计划版本差异 | 等待正式后端契约 |
| GET | `/api/v1/traces/{traceId}` | 读取完整 Agent 决策轨迹 | 等待正式后端契约 |
| POST | `/api/v1/demo/reset` | 重置演示数据，仅调试环境使用 | Fixture 已实现 |

联调前必须由后端或联调负责人确认请求字段、响应字段、错误码、鉴权方式以及 ID 传递规则。前端不应自行把缺失的 `/api/v1/exercises` 或 `/api/v1/plans` 改接到 `/api/agent` 聊天接口。

## 6. 当前已知限制与后置项

- Fixture 三道题和 67% 结果为固定演示数据，不用于验证真实评分算法。
- Fixture 的 Trace ID 和业务时间为固定值；真实联调后由后端返回。
- 当前权威学习计划与本地课程/DDL 日程分区展示，自动写入具体日期属于后置体验优化。
- 正式 OpenAPI 缺失时，只验证 Fixture，不推测或伪造真实 DTO 字段。
- 签名配置、正式发布包和多真机兼容性在发布验收阶段处理。
