## 2. Fixture 核心主链

### 2.1 初始化

1. 打开“全部工具 → 数据源设置”。
2. 点击“使用离线 Fixture”。
3. 点击“检测当前计划接口”。
4. 预期显示：`Fixture 返回 Plan V1`。
5. 如果之前完成过演示，进入 Agent Trace，点击“重置演示数据”。

### 2.2 诊断前画像

1. 打开知识画像。
2. 预期画像版本为 V1。
3. 预期“二叉树后序遍历”掌握度为 42。
4. 预期关联学习证据为 0 条。

### 2.3 练习与评估

1. 点击“开始诊断练习”。
2. 预期进入 3 道题页面；Fixture 返回很快时，“正在启动 Agent 会话…”可能无法被肉眼看到。
3. 未答完三题时，“提交诊断”应不可用。
4. 完成三题后连续点击提交按钮，预期只提交一次。
5. 预期结果：正确率 67%，掌握度 42 → 58。
6. 预期显示：Agent 状态“已完成”，状态版本 5。
7. 预期显示：Plan V2，二叉树后序遍历调整为 45 分钟。

### 2.4 更新后画像与轨迹

1. 点击“查看更新后的知识画像”。
2. 预期画像版本为 V2，掌握度为 58，证据为 1 条。
3. 返回结果页并点击“查看 Agent 决策过程”。
4. 预期依次显示 5 个步骤：学习秘书、薄弱点诊断、练习生成、学习评估、计划调整。
5. 预期状态版本从 1 连续到 5，所有步骤显示“成功”。

### 2.5 重置

1. 在 Agent Trace 底部点击“重置演示数据”。
2. 预期真实后端模式不显示该按钮。
3. 返回上一层诊断页面，预期旧的 67%、42 → 58 和 Plan V2 结果不再显示，页面恢复为可重新作答的练习状态。
4. 点击“查看重置后的知识画像”。
5. 预期恢复画像 V1、掌握度 42、证据 0 条和 Plan V1。

## 3. 慢请求与异常回归

### 3.1 错题复习链

1. 从聊天页进入“错题分析”，点击“使用模拟错题快速体验”。
2. 分析完成后点击“加入明日复习”，预期返回聊天页并出现“查看复习计划”卡片。
3. 进入复习计划，预期明天新增一条来源为错题、优先级为高的复习任务。
4. 再次打开同一错题结果并尝试加入，预期不产生重复任务，并提示该知识点已在计划中。
5. 点击“继续上传错题”，预期旧分析结果被清空；快速连续更换题目时，旧请求结果不得覆盖新题结果。

### 3.2 计划与专注闭环

1. 在学习计划中选择一项待执行任务，预期进入专注设置页时任务仍为“待执行”。
2. 在设置页点击“开始专注”，预期对应计划任务变为“进行中”。
3. 提前退出并选择“不保存，返回设置”，预期任务恢复为“待执行”。
4. 完成专注进入结算页，分别选择“完成”“部分完成”“未完成”，预期完成度、Agent 建议和保存后的任务状态随选择变化。
5. 连续点击保存或再次返回结算页，预期同一 `taskId` 只生成一条专注记录，不重复生成补做任务。
6. 保存后进入更新计划，预期只更新本次记录携带的 `planTaskId` 对应任务；存在同名任务时不得误更新另一项。
7. 返回聊天页，预期出现“查看更新计划”的下一步卡片。
8. 保存后的结算页顶部和底部均应提供返回聊天入口；返回后“查看更新计划”交接卡片仍然存在。

### 3.3 搭子与协同学习闭环

1. 从聊天页进入“学习搭子”，预期每次进入均基于当前课程、目标和空闲时间重新匹配。
2. 点击“向该搭子发起学习邀请”，预期保存匹配结果、返回聊天页并出现“查看本周计划”卡片。
3. 进入计划页，预期出现带搭子姓名、协同时间、三个协作步骤的高优先级任务。
4. 重复邀请同一搭子，预期不重复创建协同任务；再次进入搭子页时显示“查看协同任务”。
5. 将协同任务完成后再次进入搭子页，预期上一轮不再锁定当前匹配，优先展示另一位候选搭子，并允许发起新一轮邀请。
6. 发起新一轮邀请后，预期生成新的任务 ID；已完成的上一轮任务保留为历史记录，不被覆盖，也不产生同 ID 任务。
7. 启动协同任务完成一次专注并保存，预期只更新该协同任务，复盘页显示搭子与“最佳搭档”徽章。
8. 无候选人时，预期显示补充课程、目标和空闲时间的明确空状态，邀请按钮不可用。

### 3.4 计划即时刷新与路由栈

1. 在本周计划点击任一待执行任务的“延后”，预期无需退出页面，状态立即显示“已延后”；“开始任务”仍然保留，右侧按钮变为“取消延后”。
2. 点击“取消延后”，预期状态立即恢复为“待执行”，右侧按钮恢复为“延后”，无需退出页面。
3. 连续执行多轮“聊天页 → 功能页 → 返回聊天”，预期聊天页在交接消息渲染后自动定位到最后一条消息，不需要用户手动下滑。
4. 再进入“全部工具”，预期返回对话、开始任务、查看全部计划和底部导航均可正常跳转。

### 3.5 无后端服务

1. 切换到“DevEco 模拟器后端”，但不启动电脑端服务。
2. 点击“检测当前计划接口”。
3. 预期按钮显示“正在检测…”，期间不可重复点击。
4. 超时后预期提示“连接超时或网络不可用”，页面不崩溃。
5. 切回 Fixture 后，预期旧错误和旧会话不会污染 Fixture 数据。

### 3.6 快速返回

1. 在真实后端未启动时打开知识画像或当前计划。
2. 请求未结束时立即返回上一页。
3. 预期不会自动跳回旧页面，也不会出现闪退。

### 3.7 非法响应

真实后端返回空正文时，前端应提示“服务未返回可解析的数据”；返回非 JSON 正文时，应提示“服务返回的数据格式不正确”，并要求联调同学检查响应。

## 4. 配置与恢复

1. 选择 Fixture，普通关闭并重新打开应用。
2. 预期数据源仍为 Fixture。
3. 启动一次诊断后，普通关闭并重新打开应用。
4. 预期保留当前 `sessionId/traceId`，并重新向所选数据源查询状态。
5. 切换数据源后，预期旧 Workflow 会话被清除。
6. 卸载应用会清除本地偏好设置，这属于系统正常行为。

当前结果：第 1–5 项的环境与状态持久化机制已实现；Fixture 的 V2 状态已完成一次强制结束进程后的人工验证。

## 5. 真实联调接口矩阵

| 方法 | 路径 | 前端用途 | 当前状态 |
| --- | --- | --- | --- |
| POST | `/api/v1/workflows` | 创建诊断 Workflow，取得 `sessionId/traceId` | v0.2 状态化契约演示后端已实现 |
| GET | `/api/v1/workflows/{sessionId}` | 查询 Agent、状态版本和最终动作 | v0.2 状态化契约演示后端已实现 |
| GET | `/api/v1/profile/{userId}` | 读取画像、掌握度、历史和 Evidence | v0.2 状态化契约演示后端已实现 |
| GET | `/api/v1/plans/current` | 读取当前权威学习计划 | v0.2 状态化契约演示后端已实现 |
| GET | `/api/v1/exercises/{setId}` | 读取诊断练习集 | v0.2 状态化契约演示后端已实现 |
| POST | `/api/v1/exercises/{setId}/submit` | 提交答案并读取评估、掌握度更新及重规划 | v0.2 状态化契约演示后端已实现，支持幂等键 |
| GET | `/api/v1/plans/{planId}/diff` | 读取计划版本差异 | v0.2 状态化契约演示后端已实现 |
| GET | `/api/v1/traces/{traceId}` | 读取完整 Agent 决策轨迹 | v0.2 状态化契约演示后端已实现 |
| POST | `/api/v1/demo/reset` | 重置演示数据，仅调试环境使用 | v0.2 状态化契约演示后端已实现 |

联调前必须由后端或联调负责人确认请求字段、响应字段、错误码、鉴权方式以及 ID 传递规则。前端不应自行把缺失的 `/api/v1/exercises` 或 `/api/v1/plans` 改接到 `/api/agent` 聊天接口。

## 6. 当前已知限制与后置项

- Fixture 三道题和 67% 结果为固定演示数据，不用于验证真实评分算法。
- Fixture 的 Trace ID 和业务时间为固定值；真实联调后由后端返回。
- 当前权威学习计划与本地课程/DDL 日程分区展示，自动写入具体日期属于后置体验优化。
- `contracts/openapi.json` 已固化为 `api-contract-v0.2`；当前后端用于契约联调，生产联调仍需确认鉴权、错误码及真实算法服务。
- 签名配置、正式发布包和多真机兼容性在发布验收阶段处理。
