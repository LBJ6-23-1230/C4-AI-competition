## 一、规程原文（官方 PDF 摘录）

来源：`C4-AI大赛/2026"中国高校计算机大赛―人工智能创意赛"鸿蒙高校创新赛竞赛规程.pdf`

### 1. 评审方式

> 「初赛和复赛均采取**线上评审**方式，全国总决赛采取**现场答辩**的评审方式。」

初赛、复赛**不看设备、不查真机**，只有进全国总决赛才需要现场答辩。

### 2. 复赛提交物与必选性

> 「备注：以上材料，初赛阶段为必选，为可选；**复赛阶段为必选**；决赛阶段为必选」

复赛阶段的详细要求：

> 「【作品说明文档】
> • 模板要求：使用大赛官网统一模板（官网下载）
> • 内容限制：主体内容不超过页（参考资料及附录不计入总页数）
> • 格式要求：文件，命名格式为：作品说明文档 + 参赛队伍名称」
>
> 「【演示视频】
> • 内容要求：分钟内完整展示作品核心功能
> • 格式要求：文件，命名格式为：演示视频 + 参赛队伍名称」
>
> 「【演示文件 / 源代码文件 / 演示系统】
> • 内容要求：演示文件需压缩为**包**
> • 命名格式：作品名称 + 参赛队伍名称」

> 「赛题需提供的源代码文件含项目运行所需的**所有工程文件**」

### 3. 评分构成

| 类别 | 评分项目 | 说明 |
|---|---|---|
| **基础评分** | 创新性 | 鸿蒙技术创新性、产品创意、交互创新 |

规程里"测试报告"只出现在一处：

> 「操作系统智能赛题需要额外提供测试报告」

**这是"操作系统智能"方向的额外要求。我们报的是应用/Agent 方向**，不强制。

## 二、结论

**必选材料 = 作品说明文档 + 演示视频 + 源代码工程压缩包。**

**「演示文件 / 可演示的 HAP」属于基础评分里的「功能演示清晰」与附加评分的「实际可演示的文件」，即加分项 —— 不是及格线。**

**真机运行从来不是提交要求。** 规程里没有任何一条要求"作品必须在真机上运行过"。

### 为什么本地做不了（技术原因，已在文档中留存证据）

**真机侧**：我们手上唯一的真机是 **ALN-AL00，HarmonyOS 4.2.0**。

| | HarmonyOS 4.x（我们的设备） | HarmonyOS NEXT 5.0+（项目要求） |
|---|---|---|
| 内核 | 基于 **Android（AOSP）** | 纯鸿蒙，已移除 AOSP |
| 调试桥 | **ADB** | **HDB** |
| 开发人员选项里有 HDB 吗 | ❌ **没有**（已逐页确认，只有 ADB 相关项） | ✅ 有 |
| 能否运行本项目 | ❌ **不能** | ✅ 能 |

* 项目 `compatibleSdkVersion = 6.1.1(24)`，即 **API 24（HarmonyOS 6.x）**；4.2 差两代。
* 已实测：`hdc list targets` 返回 `[Empty]`；Windows 侧只识别到 `MI_00`(MTP) / `MI_01`(大容量存储) / `MI_02`(**ADB**)，**不存在 HDC/HDB 接口** —— 缺的不是开关，是整套调试桥。
* USB 调试、仅充电模式允许调试、MTP 模式**均已正确开启**，排除操作问题。

**模拟器侧**：每台模拟器实例是独立 QEMU NAT 沙箱，实测两台实例 **eth0 IP 与 MAC 完全相同**（`10.0.2.15` / `52:54:00:12:34:56`），互 ping 100% 丢包，信任设备列表为空。HarmonyOS 分布式组网依赖 softbus 在**真实局域网**上做设备发现与信任配对，模拟器无网络路径 —— 这是模拟器架构限制，不是代码问题。

### 已核实项

| 2 | Client ID | `6917617022690149565` | `module.json5` 的 `metadata.client_id` ↔ AGC「APP ID」相同 |
| 3 | **签名证书指纹** | 已登记 **4 条**，其中 2 条与本机证书精确匹配 | 见下方「指纹核对」 |
| 4 | **华为账号能力** | **已开通** | AGC「开放能力管理」中「华为账号」复选框为**已勾选**状态 |

| 7 | 代码调用链 | 完整（见下） | 逐层读源码 |

### 指纹核对（本项是此前失败的真实原因）

用纯 Python 解析 `.cer`（PEM 链）算出每张证书的两种指纹：

| 证书 | 有效期 | 证书指纹 | **公钥指纹** |
|---|---|---|---|
| **release 叶子** | 2026-09-21 → **2029-09-21** | `13:A3:03:8D:…:8B:7A:86:00` | **`36:EC:7B:02:…:FC:8D:04:B8`** |
| debug 叶子 | 2026-09-21 → 2027-09-21 | `C9:F0:D3:B7:…:6A:46:64:B6` | （同上，公钥相同） |
| 中间 CA | 2020 → 2030 | `0D:AA:8A:96:…:97:58:71:80` | `5D:4E:82:89:…:A3:AA:6C:00` |
| 根 CA | 2020 → 2049 | `DF:21:A3:C0:…:DF:3A:37` | `3A:96:9B:AE:…:AE:5A:B5:04` |

**与 AGC 页面逐条比对结果**：

| AGC 登记值 | 是否匹配本机证书 |
|---|---|
| `0B:6B:65:ED:…:F5:7C:D3` | ❌ 不匹配（历史遗留的无效值） |
| `B3:50:14:03:…:60:31:A8` | ❌ 不匹配（历史遗留的无效值） |
| `36:EC:7B:02:…:FC:8D:04:B8` | ✅ **= release/debug 叶子的公钥指纹** |
| `13:A3:03:8D:…:8B:7A:86:00` | ✅ **= release 叶子的证书指纹** |

> **结论**：AGC 现已登记正确的两种指纹（公钥指纹 + 证书指纹各一份），
> 覆盖了 AGC 可能采用的任一种比对口径。此前仅登记 `0B:6B:65:ED:…`
> 是导致华为账号登录报 `1001500001` 的**根因**；该值现已不再起作用。

### 仍需在真机上确认的两点（非配置问题）

2. **回调地址**：AGC「OAuth 2.0客户端ID（凭据）」下的「回调地址」一项，

## 五、文档中如何表述（建议原文）

> **关于华为账号登录与小艺口令**：两项功能的代码路径与平台配置（AGC 应用、OAuth Client ID、
> 客户端指纹、意图框架声明）均已完成并纳入版本管理。受本团队开发环境限制 ——
> 唯一可用真机为 HarmonyOS 4.2（基于 AOSP，调试桥为 ADB），而本项目基于
> API 24（HarmonyOS 6.x，调试桥为 HDB），两者不可互通 —— 未能完成真机联调。
> 此处如实说明而不是以模拟结果代替，以便评审判断真实完成度。

> **关于分布式跨设备接续**：`distributedDataObject` 会话已在两实例上双端建立
> （`joined session zhixue_mate_study_continuity_v1`，设备形态正确识别为手机/平板），
> 代码路径完整。跨设备数据流动的观测量测需两台 HarmonyOS NEXT 真机处于同一局域网，
> 本地不具备该条件，因此未做结论性声明。

**这样写的理由**：评分表里「规范性」明确包含"内容表达清晰度"。「如实标注边界」比含糊过去更稳，也避免评委提问时被动。
