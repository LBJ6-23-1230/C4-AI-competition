> **报告日期**：2026-09-18
> **工程版本**：`liantiao1`（路径 `E:\C4-liantiao\liantiao1`）
> **验证口径**：以后端真实 HTTP 实跑 + 前端真实编译为准，非代码阅读推断
> **一句话**：这是一个**会主动算、并且算得出来**的学习搭子 —— 它不只回答问题，
> 而是用确定性代码算出「今天最该做什么」，再把结果交给你确认。

## 1. 这个 Agent 是什么

### 1.1 产品定位

面向大学生学习场景的 HarmonyOS 应用。Agent 感知你的课程、考试倒计时、作业 DDL、
错题记录与空闲时间，算出**今天最优的一件事**，并把它变成可执行的任务。

### 1.2 关键设计：判断是"算式"不是"模型觉得"

这是本项目最值钱的一点，也是答辩的主线：

| 谁在干活 | 干什么 | 是否进 prompt |
|---|---|---|
| **大模型（通义千问）** | 只回答"下一步该叫谁"、生成自然语言回复、识别错题图片 | —— |
| **确定性代码** | 判分、掌握度更新、五因子优先级、计划重规划、主动决策 | ❌ 一行都不进 |

**推论**：**拔掉大模型，整个闭环依然跑得完。** 这一点有实测证据（见 §5.3）。

### 1.3 五层工作流与界面落点

| 层 | 职责 | 你在哪看到它 |
|---|---|---|
| 1 输入层 | 汇集课程/考试/DDL/错题/目标/空闲时间 | 首页「感知摘要」一行字 |
| 2 理解层 | 识别紧迫度、错题知识点、目标差距 | 错题分析页 |
| 3 判断层 | **挑出最优学习任务**（五因子加权） | 首页「今日最优任务」卡 |
| 4 行动层 | 生成建议、补强建议、搭子匹配、计划 | 建议页 / 搭子页 / 计划页 |
| 5 输出层 | 今日卡、诊断卡、复盘卡 | **每个终点页的「接下来」卡** |

## 4. 三条使用流程（含预期数值）

### 4.1 主流程：从 Agent 推荐到掌握度提升 ★核心闭环

这是**最该演示**的一条，全程可验证：

| 步 | 你做什么 | 你会看到 | 后台发生了什么 |
|---|---|---|---|
| 1 | 打开 App，停在**首页** | 「今日最优任务：二叉树后序遍历 45 分钟 · 考试还有 5 天」 | 后端 `POST /api/v1/agent/proactive` 用五因子算出它 |
| 2 | 点「**为什么是它**」展开 | 五行因子：`0.58 × 0.30 = 0.174` … 综合优先级 | 这是**算出来的**，不是模型猜的 |
| 3 | 点「**开始专注**」（全页唯一实心按钮） | 进入专注设置，任务已预填 | 前端写入 `focusTask` 后跳转 |
| 4 | 在「更多 → 错题分析」拍一道题 | 知识点、错误类型、3 条补强建议 | 配了 Key 时走 Qwen-VL 真实识别 |
| 5 | 结果页点「**做 3 道同类专项题**」 | 进入练习页，3 道题 | —— |
| 6 | 答案选 **A / B / A** 后提交 | **得分 66.67%**、掌握度 **42 → 58** | 服务端确定性判分 + 分档更新 |
| 7 | 往下看 | Plan V1 → V2，任务时长 **45 / 15** | Agent 触发重规划 |
| 8 | 点「**再练一组同类题**」 | 页面内重开一轮练习 | 换新 idempotencyKey，不与上轮冲突 |
| 9 | 想审计 → 点「看 Agent 决策过程」 | `secretary → exercise → assessment`，3 个工具 | trace 留痕，不含思维链 |

**这条链的四个锁死数值**（改任何一个全线崩）：

```
exercise-preorder-001  = "A"
exercise-inorder-001   = "B"
exercise-postorder-001 = "C"      ← 注意是 C
三题必须共用 knowledgePointId = "binary-tree-postorder"

提交 √√×（A/B/A） → 66.67 / 掌握度 42→58 / Plan V2 (45, 15)
```

### 4.2 专注流程（闭环更短）

```
首页「开始专注」→ 专注设置 → 专注计时 → 专注结果 → 「查看 Agent 更新后的计划」
```

计时方式：30 / 60 / 自定义（1–180 分钟）/ 正计时。
模式：**普通**（可暂停、可返回）vs **严格**（无暂停、退出需二次确认，记为 `interrupted`）。

### 4.3 数据导入流程（换成你自己的课表）

```
首页「更多」→ 课程与作业 → 「导入数据」标签 → 选 CSV/JSON 或直接粘贴 → 自动解析
```

导入后 Agent 的全部建议**切换为基于真实数据分析**。
支持中英文表头（`课程名称` 与 `courseName` 均可），未填优先级时按天数自动推断。

## 5. 怎么验证它"真的是个 Agent"

这是评委最关心的部分，也是这个项目与"普通 AI 助手"的分界。

### 5.1 证据一：一次 workflow 真的跨越多个智能体

打开「Agent 决策过程」（`AgentTrace` 页），或直接查接口：

```powershell
# 创建 workflow → 推进两次 → 读 trace
curl.exe -s -X POST http://127.0.0.1:5000/api/v1/workflows ^
  -H "Content-Type: application/json" -H "X-API-Contract-Version: api-contract-v0.3" ^
  -d "{\"goal\":\"数据结构考试80+\",\"userId\":\"demo-user\",\"maxSteps\":6}"
```

**实测结果**：

| 指标 | 实测值 |
|---|---|
| trace 事件数 | 3 |
| 不同 agent | `assessment, exercise, secretary` |
| 不同 tool | `grade_exercise, select_exercises, update_mastery` |
| 是否含模型思维链 | ❌ 不含（符合竞赛红线） |

### 5.2 证据二：分数真的随答案变化

**这是主动邀请评委现场做的事**：

| 提交 | 得分 |
|---|---|
| 全对（A/B/C） | **100.0** |
| √√×（A/B/A） | **66.67** |
| 全错 | **0.0** |

> 注意：**离线 Fixture 模式下同样成立**。这一点曾经是隐藏 bug ——

### 5.3 证据三：拔掉大模型依然跑完

### 10.2 关键结构变化：对话与能力分离

改写前，6 个意图挤在对话页的一条**横向滚动 chip** 里 —— 既看不清"每个 Agent 能干什么"，
也让首页背上"仪表盘"的包袱。改写后按参考图的思路**把两者分开**：

```
对话页（ChatMain）                    我的智能体（Index）
─────────────────                    ─────────────────
问候语 + 大输入框                      分类筛选（全部/诊断/练习/计划/…）
  ↓ 直接说                                ↓
6 个 chip 快捷意图                     两列能力卡片网格（12 项）
  ↓ 想全面看看                           每卡：图标 · 分类 · 名称
「全部 →」跳能力页                           · 一句话说明 · 可用 · 「使用 ↗」
```

**分工**：对话页用于**表达**，能力页用于**发现**。

### 10.3 四标签导航（两页一致）

```
   ◈ 对话      ▦ 智能体      ◷ 计划      ◉ 我的
```

| 标签 | 落点 | 说明 |
|---|---|---|
| **对话** | `ChatMain` | 应用启动页，直接说话 |
| **智能体** | `Index` | 能力卡片网格，点「使用」调用 |
| **计划** | `Index` 的标签 2 | 计划引导 + 建议/错题/决策轨迹入口 |
| **我的** | `Index` 的标签 3 | 身份引导 + 记录/课程入口 |

> ⚠️ **两页共用同一套标签定义**：`ChatMain` 是 0 号标签自身；切到其他标签用
> **`router.replaceUrl`**（同级导航，用 `pushUrl` 会让页面栈随每次切换增长，
> 用户在标签间来回点几次就退不出去）。

### 10.4 三个实现细节值得记下来

**① `@Builder` 参数不触发重渲染（再次踩到）**

`Index.ets` 的 `AgentCard`、`PanelRow` 等 **只接收静态常量**（`AgentSpec`），
高亮/展开状态一律在内部读 `this.xxx`。这是上一轮标签栏 bug 的同一条经验：
**ArkTS 里不要把状态当参数传给 `@Builder`**。

**② 密码字段是"视觉完整、语义占位"**

参考图1 是**手机号 + 密码 + 验证码**登录。但本工程后端**刻意不做密码体系**
（见 `docs/02` §4.2：没有需要密码保护的数据，自建密码只带来合规负担与实现风险）。

因此：

| 图1 元素 | 落地方式 |
|---|---|
| 登录 / 注册 分段 | ✅ 真实可用（注册走后端免密接口） |
| 密码登录 / 验证码登录 分段 | ✅ 视觉照做；验证码页明确提示"需接入短信服务" |
| 密码输入框 + 眼睛图标 | ⚠️ **渲染但不提交**，下方有文案标注"演示版免密" |
| 记住我 | ✅ 真实可用 |

**这样视觉 100% 对齐参考，后端一行不改。** 生产化路径是接入 AGC 认证服务。

**③ 评审逃生口必须保留**

登录页底部保留两个高显眼度入口：

```
[ 跳过登录，用演示身份进入 → ]     ← 主入口，评委永远点这个
  无网络？用离线模式进入            ← 切 Fixture，断网也能演示
```

理由不变：**评审现场任何摩擦都是风险，绝不能出现进不去的页面。**

## 11. 结构性改写：对话优先 + 多智能体归并（2026-09-18）

### 11.1 七条反馈与处理

| # | 反馈 | 根因 / 判断 | 处理 |
|---|---|---|---|
| 1 | 进去不是对话界面，把对话界面和今日学习建议搞混了 | **实现 bug**：`EntryAbility` 加载的是 `pages/Index`（工作台）；且对话页种了欢迎气泡导致欢迎引导永不显示 | 启动改加载 `pages/ChatMain`；无历史时保持空消息 → 纯对话界面 |
| 2 | 登录界面怎么没有了 | **实现 bug**：`restoreIdentity` 把"离线 Fixture"放在最前，点过离线后**永久跳过登录页** | 改为"无登录态一律先看登录页"，离线模式也走登录页 |
| 3 | 12 个 agent 太多，功能类似的合并 | 原先把**功能页**（学习记录/课程导入/专注/复盘）也当成智能体，稀释了"智能体"概念 | 按老师架构归并为 **5 个**：诊断/规划/练习/测评 + 秘书 |
| 4 | 计划界面与智能体跳转重合，换成上传 DDL / 任务安排 / 错题 | 确认重合：「计划」标签与「规划智能体」指向同一批页面 | **移除「计划」标签**，换为**「学习」标签**（DDL 上传 / 任务安排 / 错题复习 / 搭子） |
| 5 | 「我的」应该是账号密码 + 搭子 + 任务完成度 + 专注记录 | 原来只有账号管理 | 补入**我的学习搭子**卡与**学习数据**六项统计 |
| 6 | 保留功能逻辑性，不改动原有 agent 逻辑 | —— | **后端零改动**；5 张卡只是既有页面的归并展示，入口全部指向原页面 |
| 7 | 老师建议：多智能体自治学习引擎 | —— | 智能体命名与分类直接采用老师的四智能体架构（见 §3.4） |

### 11.2 指导老师愿景的落地对应

> **愿景**：以"让每个大学生都拥有自己的学习秘书"为愿景，探索人工智能时代"因人施教"的新范式。
> 以**多智能体自治学习引擎**为核心，构建**对话式画像建模**、**个性化学习计划**、
> **多智能体助学团**，通过持续理解学习者特征、动态优化专属学习路径，
> 实现学习提升的**全过程记录与可信验证**。

| 老师提法 | 项目中的落点 |
|---|---|
| 学习秘书 | 产品定位「会主动找你的 AI 学习搭子」；首屏即对话，直接说需求 |
| **多智能体自治学习引擎** | 诊断 → 规划 → 练习 → 测评，由**秘书智能体**统筹"下一步叫谁"（`secretary → exercise → assessment`，trace 留痕） |
| **对话式画像建模** | 对话页 6 类意图 + 错题诊断 → 学情画像（雷达图 + 证据） |
| **个性化学习计划** | 规划智能体五因子算最优任务，掌握度变化触发自动重规划 |
| **多智能体助学团** | 智能体页 5 张卡片 = 助学团名册 |
| **持续理解特征 / 动态优化路径** | 每次练习提交都更新掌握度与证据，并重排计划 |
| **全过程记录与可信验证** | trace 3 事件/3 agent/3 tool；判分随答案变化；105 项自检；`experiments/snapshot` 可导出 |

### 11.3 界面的逻辑性如何保持

```
        ┌──────────── 对话页（首屏）────────────┐
        │  说出需求 → 意图识别 → 卡片回复 → 跳转   │
        └───────────────┬──────────────────────┘
                        │
   ┌────────────────────┼────────────────────┐
   ▼                    ▼                    ▼
智能体页              学习页                我的页
（能做什么）          （要做什么）           （我是谁）
诊断/规划/练习/测评    上传 DDL·任务·错题·搭子   账号·数据·搭子
```

* **对话页**回答"我想做点什么" —— 最自然的入口；
* **智能体页**回答"它到底会做什么" —— 能力发现；
* **学习页**回答"我现在该处理什么" —— 高频操作；
* **我的页**回答"我的数据在哪" —— 账号与统计。

四页职责互不重叠，且**所有跳转仍落在原有页面上**。
