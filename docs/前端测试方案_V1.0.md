# 知学 Mate 前端测试方案 V1.0

## 1. 目的

确认当前前端版本能稳定运行，且用户可以从聊天页进入“薄弱诊断、错题分析、学习计划、学习搭子”四条产品主线。

本方案分为两部分：

- **当前可执行测试**：不依赖真实后端。网络不可用时，应用使用本地兜底回复和导航卡片。
- **后端联调测试**：等待后端提供可访问地址和真实接口后执行。

> 注意：二叉树练习只是历史接口/fixture 验证样例，不属于当前产品主线，也不应出现在正常用户入口中。

## 2. 测试前准备

1. 在 DevEco Studio 打开项目 `D:\zhixue_Mate`。
2. 确认环境变量 `DEVECO_SDK_HOME` 的值为：

   ```text
   D:\develop\DevEco Studio\sdk
   ```

3. 连接模拟器或调试设备。
4. 点击“运行”。应用首次进入“知学搭子”聊天页。
5. 点击右上角“新对话”，确保开始时只有欢迎消息。

## 3. 测试结果记录规则

每一项都记录为以下之一：

- `通过`：实际结果与预期一致。
- `失败`：不能完成步骤，或结果与预期不一致。
- `阻塞`：由于设备权限、后端未启动等外部原因无法判断。

发现问题时，请记录：测试编号、操作步骤、实际现象、截图、发生时间。

## 5. 后端联调测试（暂不执行）

以下项目必须等待后端提供可访问的服务地址、接口实现和测试账号后再执行。

| 编号 | 需要后端提供 | 前端验证动作 | 预期结果 |
| --- | --- | --- |
| I-01 | 聊天接口 `/api/agent/chat` | 发送“薄弱诊断” | 真实 Agent 回复和卡片正确显示 |
| I-02 | 学习画像接口 | 打开并刷新知识画像 | 目标、掌握度、证据来自后端，不使用 fixture |
| I-03 | 当前学习计划接口 | 打开计划页 | 任务、优先级和调整原因来自后端 |
| I-04 | 错题识别/分析接口 | 上传真实图片 | 返回知识点、错误类型、补强建议 |
| I-05 | 通用练习题接口及 `exerciseSetId` 来源 | 从某个薄弱知识点进入练习 | 页面按后端返回的课程和知识点显示，不写死二叉树 |
| I-06 | Trace 与重置接口 | 查看 Agent 决策过程、执行重置 | 显示真实事件；重置后数据恢复初始状态 |

## 6. 测试通过标准

当前版本满足以下条件即可视为前端基础验收通过：

1. 可以构建、安装和运行。
2. 聊天页的四条主线均能出现正确卡片并跳转到对应页面。
3. 错题分析的模拟流程可完成，并能进入学习计划。
4. 页面返回、重置聊天、空消息限制等基础交互正常。
5. 正常用户入口不出现固定二叉树测试入口。
