# 知学 Mate · Agent 运行界面信息架构 v2

> **重构日期**：2026-09-18
> **动因**：用户反馈"点开之后很难知道下一步要干嘛，各个页面和按钮的关系混乱"
> **依据**：`docs/前端README.md` 的 5 层 Agent 工作流设计初衷 + 实际导航图审计
> **结果**：前端全部编译通过（`BUILD SUCCESSFUL`），后端 104/104 自检仍全绿

---

## 1. 设计初衷（重构的判据）

产品定义是 **"会主动找你的 AI 学习搭子"**，Agent 工作流分 5 层：

| 层 | 职责 | 落到界面上的要求 |
|---|---|---|
| 1 输入层 | 汇集课程、考试、DDL、错题、目标、空闲时间 | 首页要能看见"我知道什么" |
| 2 理解层 | 识别紧迫度、错题知识点、目标差距 | —— |
| 3 判断层 | **挑出最优学习任务**（五因子） | **首页必须只有一个最优解，不是一堆选项** |
| 4 行动层 | 生成建议、错题补强、搭子匹配、计划 | 建议必须能一键变成行动 |
| 5 输出层 | 输出今日卡、诊断卡、复盘 | **每个终点页都要给出下一步** |

**核心判据**：一个 Agent 产品的首页应该像**助理汇报**（"今天最该做这一件事"），
而不是像**控制台**（"这里有 10 个功能，你自己挑"）。

## 2. 重构前的问题（实测证据）

### 2.1 首页是"平铺的功能清单"

| 指标 | 重构前 |
|---|---|
| 跳转目标 | 9 个并列 |
| 按钮 | 10 个 |
| 可点区域 | 18 处 |
| 重复的"优先级卡" | **3 个**（`ProactiveDecisionCard` / `AgentPlanCard` / `PrimaryTaskCard`）——都在回答同一个问题"今天做什么" |

**后果**：用户点进来看到的是 10 个平级选择，Agent 的"判断"被稀释成了并列入口。
README 里写的演示主线是一条**线**（首页 → 建议 → 错题 → 画像 → 搭子 → 协同 → 复盘），
代码却实现成了**辐射**。

### 2.2 底部"标签栏"是假的

```typescript
this.BottomNavItem('⌂', '首页', true,  () => {})                    // ← 原地不动
this.BottomNavItem('◷', '计划', false, () => this.openPlan())       // ← 跳 StudyPlan
this.BottomNavItem('▣', '学习', false, () => this.openLearning())   // ← 跳 CourseImport
this.BottomNavItem('◉', '我的', false, () => this.openProfile())    // ← 跳 LearningHistory！
```

三个问题：
1. 它**长得像标签栏但不是**——点任意一项都是跳转到深层页面，不是切换主视图；
2. `active` 参数**写死为 true/摆**设，用户无法从标签态知道自己在哪里；
3. **「我的」跳到 `LearningHistory`（学习记录）**，而页头身份标签却跳 `Account`——
   同一个"我"有两个不同去处。

### 2.3 四个页面是"死胡同"

| 页面 | 重构前出口 | 问题 |
|---|---|---|
| `WrongQuestion` 错题分析 | **无** | 诊断出薄弱点，却不让你练 |
| `ApiEnvironment` 接口环境 | **无** | 只剩 `back()` |
| `ExercisePractice` 练习 | 只有"返回首页/看画像/看决策" | **恰恰没有"再练一次"**，核心闭环在最后一格断掉 |
| `StudyTags` 知识画像 | 只有"刷新画像/诊断" | 知道了哪里弱，拿不到"现在就去补"的动作 |

## 3. 重构后的信息架构

### 3.1 首页：一个最优下一步 + 真实标签栏

```
┌─────────────────────────────────────────────┐
│ 知学搭子            ● 体验身份      对话 ←  │  页头：身份可点进「我的」
├─────────────────────────────────────────────┤
│  [Agent 状态条]                              │  它现在在干什么
│                                             │
│ ┌─────────────────────────────────────────┐ │
│ │ 今日最优任务            Plan V2         │ │  ★ 唯一主行动
│ │ 二叉树后序遍历                          │ │    三个候选来源合并为一张卡
│ │ 45 分钟 · 考试还有 5 天                 │ │
│ │ ┌─────────────────────────────────────┐ │ │
│ │ │ 为什么是它          展开 ↓          │ │ │  结论先行，公式折叠
│ │ │ 考试剩 5 天、这道题你只答对 2/3     │ │ │
│ │ └─────────────────────────────────────┘ │ │
│ │ ┌─────────────────────────────────────┐ │ │
│ │ │          开始专注                    │ │ │  ★ 全页唯一实心按钮
│ │ └─────────────────────────────────────┘ │ │
│ └─────────────────────────────────────────┘ │
│  已掌握 3 门课程、2 项临近作业 · exam_within_7d│  感知摘要
│                                             │
│ [今日专注分钟] [本周完成度] [待处理作业]      │  状态指标
│                                             │
│ ┌─────────────────────────────────────────┐ │
│ │ 更多                        展开 ↓      │ │  窄入口，默认收起
│ └─────────────────────────────────────────┘ │
│  开发调试：数据源设置                配置 →  │  降级到底部
├─────────────────────────────────────────────┤
│   ⌂ 首页    ◷ 计划    ◵ 记录    ◉ 我的      │  ★ 真实标签栏
└─────────────────────────────────────────────┘
```

**三个关键改动**：

1. **三个重复的优先级卡合并成一个** `PrimaryActionCard`。候选来源按可靠性排序
   （后端 proactive 决策 → 后端当前计划 → Fixture 任务 → 兜底诊断练习），
   **永远只渲染一个按钮**。
2. **底部标签栏变成真的**：4 个标签切换主视图（首页 / 计划 / 记录 / 我的），
   有正确的 `active` 态，用户始终知道自己在哪。
3. **修掉"我"的双重身份**：页头身份标签与「我的」标签**都指向 `Account`**。

**量化对比**：

| 指标 | 重构前 | 重构后 |
|---|---|---|
| 首页按钮 | 10 | **5** |
| 首页可点区域 | 18 | **12** |
| 重复优先级卡 | 3 | **1** |
| 首页代码行数 | 727 | **608（-119）** |
| 标签栏行为 | 假（跳深层页） | **真（切主视图）** |

### 3.2 补齐 Agent 闭环：`FollowUpCard` 组件

新增 `components/FollowUpCard.ets`，统一收口"下一步该做什么"。

**三条使用纪律**（写在组件注释里）：
1. **一个页面只用一次**，放在内容流末尾，作为"然后呢？"的唯一答案；
2. `primaryText` 是**唯一**实心按钮，其余最多一个描边按钮（遵循项目设计规范）；
3. 文案必须是**具体动作**，不是"查看详情"这类空泛词。

**已接入的三个关键节点**：

| 页面 | 主行动 | 为什么 |
|---|---|---|
| `WrongQuestion` | 做 3 道同类专项题 → `ExercisePractice` | 诊断出薄弱点却不让你练 = 行动层断开 |
| `ExercisePractice` | **再练一组同类题**（页面内重开） | ★ 核心闭环最后一格：看到分数变了却不知道干嘛 |
| `StudyTags` | 按薄弱点开始专项练习 → `ExercisePractice` | 知道哪里弱，需要一个"现在就去补"的动作 |

> `ExercisePractice` 的"再练一组"用**页面内重开**（`restartPractice()`）而非
> `router.pushUrl` 跳回自身——后者会把同一页面反复压进栈，用户按返回要退好几层。
> 重开会重置作答并换新的 `idempotencyKey`，不与上一轮提交冲突。

### 3.3 决策过程的分层暴露（回应"不要在前端暴露 agent 决策流程"）

**结论：不删，但分层。** 理由分场景：

* **参赛演示场景必须显式** —— Agent 赛道评审明确要求"Agent 自己连续调用 ≥2 个智能体"，
  不给证据等于没做；它也是答辩最强的一页（评委问"为什么推荐先学二叉树"，
  打开逐行念贡献值，从"模型觉得"变成"算式算的"）。
* **真实用户体验场景要收敛** —— `0.58 × 0.30 = 0.174` 是工程语言不是用户语言；
  一个高级 Agent 的标志恰恰是**不用解释自己怎么想的**。

**分层方案**：

| 层 | 内容 | 给谁看 |
|---|---|---|
| 主流程文案 | 自然语言一句："考试还有 5 天，你上次这道题只答对 2/3，所以先补它" | 全部用户 |
| 「**为什么是它**」折叠 | 五因子明细 + 算式 | 想深究的用户；**演示时手动展开** |
| `AgentTrace` 页 | toolCalls / stateVersion / evidenceIds 全部技术元数据 | 评委、调试 |

**`FactorBreakdownCard` 的实际改动**：

| 项 | 改前 | 改后 |
|---|---|---|
| 标题 | 「Agent 的判断依据」 | 「**为什么是它**」 |
| 折叠态 | 「展开查看各因子的数值、权重与贡献」（说明书语气） | **结论先行**：直接给 `reason` 人话 |
| 边框 | `#BFDBFE`（强调） | `#E2E8F0`（常规，不再抢主按钮的视觉焦点） |
| `AgentTrace` 入口 | 首页底部一个平级按钮 | 收进「更多」，并作为 `FollowUpCard` 的"想知道为什么？" |

## 4. 重构后的完整导航图

```
Login ──→ Index ─┬─→ FocusSetup ─→ FocusTimer ─→ FocusResult ─→ StudyPlan
   ↑             ├─→ ExercisePractice ─→ StudyTags ─→ StudyPlan
   │             ├─→ WrongQuestion ─→ ExercisePractice
 Account ────────┤      ↑
   │             ├─→ StudySuggestion ─→ FocusSetup
   │             ├─→ PartnerMatch ─→ StudyPlan
   │             ├─→ CourseImport ─→ StudyPlan
   │             ├─→ LearningHistory ─→ FocusSetup
   │             ├─→ AgentTrace ─→ StudyTags
   │             └─→ ApiEnvironment（调试页，仅 back）
   └─ 返回登录页
```

**闭环已成立**：
```
首页（Agent 推荐）→ 专注/练习 → 判分 → 掌握度更新 → 计划重排
   ↑                                                      │
   └──────────── FollowUpCard「再练一组」←────────────────┘
```

**每个页面的出口**（重构后实测，无死胡同业务页）：

| 页面 | 主出口 | 说明 |
|---|---|---|
| `Index` | 主行动 CTA 唯一 | 其余收进「更多」 |
| `WrongQuestion` | → `ExercisePractice` | ✅ 新增闭环 |
| `ExercisePractice` | → 页面内重开 / `StudyTags` | ✅ 新增闭环 |
| `StudyTags` | → `ExercisePractice` / `StudyPlan` | ✅ 新增闭环 |
| `StudyPlan` / `StudySuggestion` | → `FocusSetup` | 原有 |
| `FocusResult` | → `StudyPlan` | 原有 |
| `PartnerMatch` | → `StudyPlan` | 原有 |
| `ReviewSummary` | → `ChatMain` / `StudyPlan` | 原有 |
| `AgentTrace` | → `StudyTags` | 原有 |
| `ApiEnvironment` | 仅 `back()` | 开发调试页，合理 |
