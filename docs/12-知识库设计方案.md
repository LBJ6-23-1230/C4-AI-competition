## 一、为什么这个方向是对的

原文定的方向是：把「知学 Mate」升级成**「基于个人课程资料的 AI 学习搭子」**。核心理由：

**当前系统有一个叙事缺口**：Agent 的所有判断（优先级、薄弱点、错题、搭子匹配）
都建立在**内置演示数据**上。评委最可能追问的一句是：

> **"你的 AI 凭什么说这个知识点薄弱？依据是什么？"**

现在的回答只能是"规则算出来的"。而知识库能给出**有来源的回答**：

```
"依据你上传的《数据结构期末复习讲义.pdf》第 3 章，
 二叉树遍历出现频次最高（12 处），且你连续两次在该知识点出错。"
```

**这一句话就把系统从"规则演示"提升到"有依据的个性化助学"。**

而且它和现有的三条主线天然咬合（原文第 3 阶段的表格已经指出）：

| 现有能力 | 接入知识库后 |
|---|---|
| AI 答疑 | 从**你自己的讲义**检索，答案附页码/文件 |
| 错题诊断 | 关联到资料中的**具体章节与例题** |
| 学习计划 | 按薄弱点优先推荐**知识库里的对应章节** |
| 练习生成 | 基于检索到的资料出题，**不脱离课程范围** |

## 三、分三期落地（对齐原文，但给出可执行细节）

### 第一期：页面与演示闭环（**建议先做这个**）

**目标**：不管底层真假，先让评委看到完整交互。

原文要求：支持按课程创建知识库；上传 `PDF、TXT、Markdown、CSV、JSON`；
展示文件名、所属课程、处理状态、知识点标签、上传时间；重点展示"AI 从你的资料中学到什么"。

**我的补充（关键）**：

1. **处理状态要真实反映后端状态**，不要假装。四态：
   `uploading` → `parsing` → `ready` / `failed`
   （失败态必须可见 —— 评委看到"能失败、能重试"比看到永远成功更可信）

2. **"AI 从资料中学到什么"要有具体数字**，不要空话：
   ```
   《二叉树复习讲义.pdf》
     → 识别 3 个知识点：二叉树遍历、递归、树的深度
     → 提取 12 个可用于出题的片段
     → 自动生成 2 个常见易错点
   ```
   数字从后端 `parse_result` 里来，**不是前端编的**。

3. **上传要支持"演示样例"按钮** —— 和错题页的"使用模拟错题快速体验"一致。
   评审现场不该让评委等你传文件。

**交付物**：4 个页面 + 后端可返回真实解析结果的 JSON 存储。

### 第二期：接入后端检索

原文要求：文件上传与元信息管理、文本提取与分段切片、知识点标签提取、
基于关键词/标签的检索接口、返回命中的原文片段与来源文件。
并明确指出：**第一版不必立即上向量数据库，JSON/SQLite + 关键词检索够用**。

**我完全同意，并补充落地方案**：

#### 切片策略（决定检索质量）

```
按语义边界切，不要按固定字数硬切：
  ① 优先按 Markdown/HTML 标题切（# / ##）
  ② 其次按空行段落切
  ③ 单段过长（>800 字）再按句子切（。！？；）
  ④ 每片带 1 句重叠（overlap），避免答案被切断

每片存：chunkId, documentId, courseId, text,
        headingPath(如 "第3章 > 3.2 遍历"), charStart, charEnd, tokens
```

> `headingPath` 是**引用标注的关键** —— 有它才能说"第 3 章 3.2 节"，
> 而不只是"某个文件里"。

#### 知识点标签提取（不依赖大模型也能跑）

```
① 词表匹配：把 StudyTags 已有知识点 + 课程名 + 用户薄弱点组成词表，
   在切片文本里做匹配 → 命中的打标签（确定性、可复现、答辩友好）
② 术语候选：高频的 2–6 字中文名词短语（TF 排序取 TopN）
③ 有大模型时：让 LLM 从切片里抽 3–5 个知识点（失败自动回退 ①②）
```

**为什么强调"不依赖大模型也能跑"**：与现有架构的设计纪律一致 ——
**业务计算(判分/掌握度/优先级)留在确定性代码里，模型只做它擅长的**。
标签提取也应是"规则打底 + 模型增强"。

#### 检索第一版（关键词 + 标签）

```
score = 0.5 * 标签命中 + 0.3 * 关键词命中(BM25 或 TF-IDF) + 0.2 * 标题层级权重
取 TopK（K=5），返回 chunk 文本 + headingPath + 文件名
```

> 中文分词没把握时，**用 2-gram 切分**就能跑出可用效果，不必引入 jieba。

**交付物**：`/search` 返回真实命中片段；检索测试页可对比"有/无知识库"的回答差异。

### 第三期：RAG 与个性化学习

原文的四点（答疑 / 错题 / 计划 / 练习生成）我都同意。补充**工程要点**：

| 要点 | 做法 |
|---|---|
| **引用必须可回溯** | 每个回答带 `[{documentId, fileName, headingPath, chunkId}]`，前端可点开看原文 |
| **检索失败要诚实** | 知识库里没有相关内容时，明确说"你的资料里没有找到相关章节，以下是通用建议" —— **不要假装** |

| **embedding 来源** | DashScope `text-embedding-v3`（与现有 Qwen 同一 Key，**零额外接入成本**） |

## 四、数据模型设计

沿用现有 `JsonRepository` 的集合式结构（升级到 SQL 时可直接映射为表）。

### 4.1 `knowledge_bases` —— 知识库（按课程）

```json
{
  "kbId": "kb-ds-final",
  "userId": "u-xxx",
  "courseName": "数据结构",
  "name": "数据结构期末复习库",
  "description": "第 1-8 章讲义 + 历年题",
  "documentCount": 3,
  "chunkCount": 128,
  "knowledgePoints": ["二叉树遍历", "图算法", "递归"],
  "createdAt": "2026-09-20T10:00:00Z",
  "updatedAt": "2026-09-20T10:05:00Z"
}
```

> `userId` 必填 —— **知识库是个人资料，必须做数据隔离**。
> 这一点尤其重要：审计已发现当前多个端点忽略 `g.current_user`（缺陷 A），
> 新模块**不要重复这个错误**。

### 4.2 `documents` —— 文档

```json
{
  "documentId": "doc-a1b2",
  "kbId": "kb-ds-final",
  "userId": "u-xxx",
  "fileName": "二叉树复习讲义.pdf",
  "mimeType": "application/pdf",
  "sizeBytes": 248320,
  "status": "ready",
  "statusMessage": "",
  "charCount": 18420,
  "chunkCount": 42,
  "knowledgePoints": ["二叉树遍历", "递归理解"],
  "errorPointCandidates": ["前序/中序/后序访问时机混淆"],
  "uploadedAt": "2026-09-20T10:00:00Z",
  "parsedAt": "2026-09-20T10:00:03Z"
}
```

`status` 取值：`uploading` | `parsing` | `ready` | `failed`

### 4.3 `chunks` —— 切片（检索单元）

```json
{
  "chunkId": "chk-0001",
  "documentId": "doc-a1b2",
  "kbId": "kb-ds-final",
  "userId": "u-xxx",
  "text": "后序遍历的顺序是左-右-根，因此根节点总是最后被访问……",
  "headingPath": "第3章 > 3.2 二叉树遍历 > 3.2.3 后序遍历",
  "charStart": 3120,
  "charEnd": 3340,
  "knowledgePoints": ["二叉树遍历"],
  "tokens": 86
}
```

### 4.4 `citations` —— AI 引用记录（对应原文"AI 引用记录"页）

```json
{
  "citationId": "cit-0001",
  "userId": "u-xxx",
  "sourceType": "chat",          // chat | diagnosis | plan | exercise
  "sourceId": "msg-0042",
  "query": "二叉树后序遍历为什么总是根最后访问？",
  "chunkIds": ["chk-0001", "chk-0017"],
  "createdAt": "2026-09-20T10:10:00Z"
}
```

> 这张表是**答辩素材**：能统计"AI 回答中有多少比例有据可依"。

## 五、接口契约设计

遵循现有约定：路径前缀 `/api/v1/`、需 `X-API-Contract-Version: api-contract-v0.3` 头、
错误体 `{errorCode, message, details}`、响应必须过前端 `ApiResponseValidator`。

### 5.1 知识库

```
GET    /api/v1/knowledge-bases                  列出当前用户的知识库
POST   /api/v1/knowledge-bases                  { courseName, name, description? }
GET    /api/v1/knowledge-bases/{kbId}
DELETE /api/v1/knowledge-bases/{kbId}
```

### 5.2 文档

```
POST   /api/v1/knowledge-bases/{kbId}/documents     上传（multipart 或 base64）
GET    /api/v1/knowledge-bases/{kbId}/documents     列表
GET    /api/v1/documents/{documentId}               详情（含知识点、易错点）
DELETE /api/v1/documents/{documentId}
POST   /api/v1/documents/{documentId}/reparse       重新解析（失败重试）
```

**上传请求体**（与现有 `image` base64 风格一致，避免引入 multipart 复杂度）：

```json
{
  "fileName": "二叉树复习讲义.pdf",
  "mimeType": "application/pdf",
  "contentBase64": "JVBERi0xLjQK...",
  "sizeBytes": 248320
}
```

> 加护栏（吸取本轮教训）：`fileName` ≤ 200 字符、`contentBase64` ≤ 10MB、
> 单库文档数 ≤ 50、只允许白名单 MIME。

### 5.3 检索

```
POST /api/v1/knowledge-bases/{kbId}/search
  { "query": "后序遍历的顺序", "topK": 5, "knowledgePointId": "binary-tree-postorder" }

→ { "query": "...", "hits": [
      { "chunkId": "chk-0001", "documentId": "doc-a1b2",
        "fileName": "二叉树复习讲义.pdf",
        "headingPath": "第3章 > 3.2.3 后序遍历",
        "text": "……", "score": 0.87, "knowledgePoints": ["二叉树遍历"] } ],
    "totalScanned": 128, "retrievalMode": "keyword+tag" }
```

`retrievalMode` 明确标注检索方式（`keyword+tag` / `vector`）—— **诚实标注，便于答辩**。

### 5.4 与现有 Agent 的挂接

```
POST /api/agent/chat  请求体增加可选字段：
  { "message": "...", "kbId": "kb-ds-final" }

→ 响应增加可选字段：
  { "reply": "...", "intent": "...", "card": {...}, "llmUsed": true,
    "citations": [ { "fileName": "...", "headingPath": "...", "chunkId": "..." } ] }
```

**向后兼容**：`kbId` 不传则行为完全不变（不检索）。
这样**不会破坏现有 75 项联调与基线**。

## 八、答辩怎么讲

### 核心叙事

> **「我们的 AI 不是凭空给建议，它读你的课程资料」**
>
> "上传《二叉树复习讲义.pdf》后，系统提取出 42 个知识片段、
> 识别 3 个知识点、生成 2 个易错点。
> 当你问'后序遍历为什么根最后访问'，Agent 的回答会标注
> **来源：第 3 章 3.2.3 节** —— 你可以点开看原文。"

### 必须主动承认的边界

> "当前检索是**关键词 + 标签**，不是向量检索 —— 这是刻意的：
> 课程资料量小的时候关键词检索更可复现、更好排查。
> 向量检索的接入点已经预留（`retrievalMode` 字段已区分），
> 资料量上去后切 pgvector 即可。"

### 为什么这个方向比"再加一个功能"值钱

现有系统的所有判断都基于**内置演示数据**。知识库改变的是**依据的来源**：

| | 之前 | 之后 |
|---|---|---|
| 说"二叉树遍历薄弱" | 因为规则算出来 | 因为**你的讲义里这个知识点出现最多 + 你错了两次** |
| 给复习建议 | 模板文案 | 指向**你资料里的具体章节** |
| 出练习题 | 内置题库 | 从**你的资料**生成，不脱离课程范围 |

**一句话**：从"演示一个学习助手"变成"**它真的在用我的资料帮我学**"。
