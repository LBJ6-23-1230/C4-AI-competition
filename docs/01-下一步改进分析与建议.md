## 1. 本次联调到底改了什么（可作为文档/答辩素材）

### 1.1 架构级：两个后端合并为一个

**问题**（来自 `_docs/02` B-7）：B1 与 B2 行为不同源，最危险的是——前端 `WorkflowViewModel` 指向的 B1 **不执行真实 Agent 循环**，于是"Agent 自己连续调用 ≥2 个智能体"这个核心验收项，**在前端链路上根本不成立**。

**做法**：把 B1 的"自然语言层"（LLM 意图识别 + 7 个 Prompt 模板 + Qwen-VL 识图 + 对话历史 + 前端数据注入）**移植进 B2**，形成单进程、单端口、单 `baseUrl` 的统一后端。

```
修复前： 前端 ─┬─► B1:5000  /api/agent/chat  （真 LLM，但判分恒 67）
              └─► B2:5000  /api/v1/**       （真循环，但前端没接对）

修复后： 前端 ──► 统一后端:5000 ─┬─ /api/agent/chat    自然语言层（真 LLM）
                                └─ /api/v1/**         结构化工作流层（真 Agent 循环）
```

**收益**：这一个改动同时消灭了 P0-2、P1-5、P1-8 三个问题——**比逐个打补丁更彻底，因为病根是"不同源"**。

### 1.3 联调发现的一个**文档里没写过的新缺陷**（已修）

**离线 Fixture 的判分也是假的。**

`FixtureApiTransport.assessment()` 原来把 `score: 67` 写死。当 App 切到「离线 Fixture」（这是**推荐给评委的兜底演示模式**）时，`ExercisePractice` 页显示的分数就是固定的 67——**和原来 B1 的缺陷一模一样，只是换了位置**。

> 顺带修掉一个数据不一致：离线 `plan()` 原来只返回 1 个任务（`task-postorder`），
> 而它的 `planDiff()` 却声称改动了 2 个任务（含 `task-graph`）——**自己和自己矛盾**。

## 2. 现在还存在什么问题（按严重程度）

### 2.1 🔴 P0-A：用户身份分裂（做任何身份相关功能前必须先修）

**现象**：

| 位置 | 用户 ID |
|---|---|
| 前端 `MockData.ets` 的 `mockCurrentUser.userId` | **`u001`** |
| 前端 `ExerciseViewModel.ets` 兜底 | **`demo-user`** |
| 后端所有接口的默认/演示用户 | **`demo-user`** |

**为什么危险**：`Index.ets` 把 `appState.currentUser.userId`（= `u001`）直接传给 `ProactiveViewModel.load()`；而 `ExerciseViewModel.submit()` 里写的是 `submission.userId ?? 'demo-user'`。

于是同一次演示里：
- 首页主动建议按 **`u001`** 查画像；
- 练习提交与画像页按 **`demo-user`** 读写。

**如果后端将来按 `userId` 分片存储（复赛要求多用户演示、或加上登录功能后），这两个页面会读到不同的掌握度**——首页说"掌握度 42 需要补强"，画像页说"58 已经巩固"。**这是评委最容易当场击穿的那类矛盾。**

**建议**（30 分钟）：在 `ApiDefaults.ets` 增加 `DEMO_USER_ID: string = 'demo-user'`，把 `MockData.mockCurrentUser.userId` 与所有 `?? 'demo-user'` 兜底统一引用它。

**验收**：`grep -r "u001" entry/src/main/ets` 结果为空（或只剩候选人数据）。

#### 做服务卡片时的三条工程纪律（容易踩坑，务必先读）

1. **卡片是受限环境**：ArkTS 卡片**不能**直接发网络请求、不能用大部分状态管理。
   正确做法：`EntryAbility`（或后台任务）算好后用 `formProvider.updateForm(formId, data)` **推**给卡片。
2. **卡片刷新有频率限制**：不要依赖"每分钟刷新"。走**事件驱动**——用户完成专注、完成练习、DDL 变化时主动 `updateForm`。
3. **尺寸做两套**：2×2 显示"今日任务 + 时长"；2×4 多一行 Agent 理由（`reason`）。
   > `reason` 那行是**答辩最强的一句话**，别浪费。

`demo/reset` 的 `mastery=42`、Plan V1 `[30,30]`、提交后 `66.67 → 58`、Plan V2 `[45,15]`，
以及"带上登录 token 访问 demo-user 接口，结果必须与游客逐字节一致"。
